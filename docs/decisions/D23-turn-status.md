# D23. 轮次状态行：宿主的控件、宿主的数据

- **状态**：已实施
- **分组**：功能

## 决定

- 宿主把每一轮的「过程」控件（ui-chat 的 turn-process：进行中「深度求索中，用时 N 秒」，停止与失败后「已停止」「处理失败」）排在这一轮最前面。进行中、已停止与失败的轮次里，这个控件改做状态行、排到这一轮的工作之后；正常结束的一轮保留宿主的控件与位置，它负责折叠这一轮的工作。
- 不另建元素、不移动节点：对话列本是纵向 flex，脚本按文档顺序给列里的行写内联的 `--dsh-claude-turn-order`，样式表只对带这个属性的行取 `order`。第一个要移动的控件之前的行保持 0；每个要移动的控件排在它这一轮最后一行（页脚 `turn-tail` 除外）之后，从那里起的行逐级加一层，历史里多处停止或失败的轮次各自排对。标记与顺序每轮重算，不再需要的当场撤掉。
- 控件画成 Claude Code 的状态行：火花加一行文字。进行中为「用时 · 输出 tokens · 当前动作」，火花转动；已停止或失败为「宿主的已停止 / 处理失败 · 用时 · 输出 tokens」，火花静止。状态写在 `data-dsh-claude-turn-state`（`live` / `stopped` / `failed`），文字写在 `data-dsh-claude-turn-status`，样式表用 `attr()` 画出来；宿主自己的标签留在 DOM 里只是不显示。
- 数字只读宿主的聊天快照 `uiConversation.binding(会话 id).target('chat')`：会话 id 取对话区外层的 `data-conversation-session`；状态与结束原因取这一轮的 `status` 与 `turn/end` 的 `reason.kind`（`aborted` / `error`）；用时取 `turn/start` 到现在或到 `turn/end`；输出 tokens 是已结束各步上报的 `usage.outputTokens` 之和，不做估算。
- 当前动作按最新一步的助手输出判断：最后一块是推理为「思考中」，推理之后开始输出正文或工具调用为「思考了 N 秒」，没有推理时为「输出中」或「准备调用工具」；这一步没在输出时，有进行中的工具调用为「运行工具中」，否则为「等待模型」。快照不带推理的时间戳，「思考了」的时长是本页面看到推理出现到结束的时间。
- 时长写法与「已停止」「处理失败」两个词用宿主 `chat` 文案表里的原文。
- 状态行没有自己的计时器：宿主的时钟每秒改写一次标签文字，这次改动触发的刷新顺带更新状态行。

## 理由

- 状态行在工作过程的末尾，正在发生什么、停在哪里、为何失败都挨在一起，和 Claude Code 一样；完成、停止、失败与折叠仍是宿主的行为。

## 代价

- 依赖对话列是纵向 flex、行上的 `data-chat-flow-kind` / `data-chat-turn` 与聊天快照的现状。
- 读屏与 Tab 键仍按文档顺序先经过这个控件；历史里有停止或失败的轮次时，它之后的每一行都带一个内联顺序值。

## 重审条件

- 宿主提供可替换的轮次状态插槽，或把这个控件移到这一轮末尾时，改用宿主的。
