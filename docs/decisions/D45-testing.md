# D45. 三层测试与持续集成

- **状态**：已实施
- **分组**：分发与流程
- **关联**：D40、D44、D46、D47

## 决定

- 单元测试（Vitest，浏览器模式跑在本机 Chrome 上）覆盖纯逻辑：弹簧曲线、气泡形状采样、折行分段、吉祥物状态机、偏好解析、观察总线的分发顺序（D40）、滚动主人的仲裁与接管（D41）。毫秒级，改一行就能跑。
- 契约测试见 D44：宿主选择器与入口逐条对着真实页面核对。
- 端到端测试（Playwright）跑在装配好的宿主上：
  - `packages/testing/dsh-web.cjs` 起一个临时实例：`$DSH_HOME` 在 `.debug/` 下，本仓库以链接装进它的 web 配置，启动后交出带令牌的地址；通道自己的补丁走 `--patch` 覆盖层，profile 的用户层留给宿主；`resetState` 清掉会话与侧栏缓存，断言页面的场景因此从空会话列表开始。实例的标准输入是一条只由启动进程持有的管道，`packages/testing/lifeline.cjs` 经 `NODE_OPTIONS` 预加载进宿主，读到管道关闭就结束宿主：启动进程无论正常退出、抛出未捕获的错误、被 Ctrl+C 或 `taskkill /F` 终止，实例都随它结束，不会留在后台。
  - `packages/testing/mock-llm.cjs` 是脚本化的模型服务，按 Messages 协议回答宿主路由，脚本按请求顺序交付；只有模型是脚本化的，agent 循环、会话、客户端各层与渲染都是发行版宿主。
  - `packages/testing/e2e.cjs` 的每个场景各起一套实例，断言各自的东西：`conversation` 读者的消息成行、脚本回答的 Markdown 与思考过程归组；`narrow` 以 390×844 的手机窗口打开，断言输入框下沿那一行放得下权限档位、模型、推理等级与上下文圆环（权限收起下三角、两个选择器按窄屏上限截断、圆环不显示数字、四者都在卡片内且圆环不与旁边重叠）；`statsPosition` 用补丁层把「对话统计信息位置」存成「独立成行」，断言这个值经宿主的设置命名空间到达页面、宿主的统计行与计量环在卡片下面排成自己的一行、皮肤自己的数字块没有建起来（`packages/testing/stats-position.cjs`：存档值与宿主设置表单这一段路，替代的宿主页面证明不了）；`statsOverlay` 在「收进上下文」那一档下把计量环所在的 dock 与输入行两个盒子逐边对起来，把卡片在那一行下方留的空隙分别改成 0 与 16px 断言 dock 跟着那一行走、不停在写死的 4px 上，再把触发按钮在停放节点里左移 14px 断言行尾留出的宽度按两个盒子的并集算（`packages/testing/stats-overlay.cjs`；两个场景由 `stats-position.cjs` 一次导出，场景表所在那一份停在停止线上，长度不再增长）；`tool` 工具调用单独成行并带调用编号、结果之后的回答渲染出来；`send` 发送起飞期间替身离开页面、真行不可见、读者的字每一帧都看得见、替身带走了输入卡片的字体；`scroll` 逐帧记录滚动位置与内容高度，断言没有一帧在内容没有变短时倒退、没有一帧在内容没有增长时把尾部留在视野之外；`readerScroll` 在轮次进行中自己滚一次滚轮，断言状态行的固定只在跟随自己移动位置时钉住、读者往回翻看时该行随内容走而不浮在内容上，它自己逐帧采样（`packages/testing/reader-scroll.cjs`：`packages/testing/e2e.cjs` 已到停止线，新场景各成一个模块，场景表仍在那份里）；`processSummary` 让脚本化的模型先沉默过 10 秒再开口（`packages/testing/mock-llm.cjs` 的 `holdMs`），断言运行中那一行换成皮肤的等待行、计时用宿主的单位、过 10 秒挂出「暂未响应」、模型一开口就撤下，并在轮次结束后按每个过程组标题上的计数核对它收住的东西（`packages/testing/process-summary.cjs`）；`importance` 走过首页、对话、草稿、流式输出、各个弹层与菜单、附件、暗色与品牌和配色的切换以及每条 `:hover` 规则的悬停，逐条判定皮肤的 `!important` 是否需要，一条多余即失败；设置 `DSH_IMPORTANCE_REFERENCE` 时每个状态还与一张旧样式表逐元素比对（D51）；`shots` 亮暗两套截图。
  - 截图沿用写盘前的隐私替换与泄漏扫描（`scripts/shared/privacy.cjs`，与 `scripts/shoot.cjs` 共用），两套明暗各写一张到本次运行的输出目录供人查看；仓库不存比对基线，画面是否变样由用户看过再定。
- 持续集成（`.github/workflows/ci.yml`）：构建检查、单元测试与完整冒烟在 Linux 上跑；完整冒烟另在 Windows 上跑一遍，读者的桌面端在 Windows，宿主半边在那里读会话目录、盘符路径与文件时间；端到端的行为场景与截图捕获在 Linux 上跑，宿主版本固定；`contract` 场景另对宿主最新的预发布版（npm 的 `alpha` 标签）跑一遍，宿主改动了皮肤读的契约时先在这里报出，只作预警，不挡合并。每个任务都有时限；工作流用到的 Actions 由 Dependabot 每周提更新（`.github/dependabot.yml`）。
- `.debug/` 里有价值的探针已升级为有维护的工具：逐帧滚动记录并入 `packages/testing/e2e.cjs` 的 `scroll` 场景，发送过程录制并入 `send` 场景的逐帧采样，替身采样并入同一份采样；其余草稿在会话结束时删除。

## 理由

- 冒烟跑在替代宿主页面上，发现得了结构与标记的回归，发现不了真实宿主的时序问题；只靠人工运行的探针又把这类问题留给了下一次手工排查。

## 代价

- 持续集成要装 DSH、pnpm 与 Chrome，端到端部分耗时以分钟计；截图基线随视觉改动刷新。

## 重审条件

- 宿主提供官方的插件测试环境时改用宿主的。
