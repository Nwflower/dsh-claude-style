# D53. 用量两个来源按日期合并

- **状态**：已实施
- **分组**：运行时
- **关联**：D11、D12
- **现状**：本条改写「账本只在它覆盖最新会话活动时被采用」的旧规则。此前只要账本的最新一天早于最新一条会话活动（成本计量插件停写就会出现），整份账本被丢弃，面板改用本地折算，账本里那些日志已清掉的日子随之从面板上消失。

## 决定

- 成本计量插件的账本与本地折算（`usage.ts`、`usage-fold.ts`）是同一批日子的两本账，按日期合并，绝不按金额相加：账本认识的一天就是账本的一天，只有账本最新一天之后的日期来自折算。
- `totals` 按合并后的日图重算，`sessions` 取两边的并集（账本每天的会话 id，加上最后写入落在未覆盖日期的会话日志 id），`activeDays` 是合并后的天数。
- 路由先把账本自己算出的结果交出去（`publish`），折算完成后换成合并结果，所以账本再旧也能立刻显示它覆盖的全部历史。
- `source` 在折算补进过日期时写 `cost-meter+local`，完全没有账本或账本补不上时写 `local`；两个值都不改变面板的取数路径。
- 折到账本已覆盖日期的会话照旧留在折算缓存里，读它们的账本日不与之相加。
- 账本不存在、解析不了或版本不认时，整条路径与从前一致：只用本地折算（D12）。

## 理由

- 两本账说的是同一批日子：相加等于同一批结算被计两次，丢弃等于拿日志还在的一部分去顶替全部。
- 账本比会话日志活得久（日志清掉的日子仍留在账本里），合并后总量对「全部」与两个窗口都自洽。
- 折算只补缺口的那一天，账本停写不再让历史一起消失。

## 代价

- 折算仍要遍历全部会话日志，成本由缓存摊平（只有变更过的日志重读）。
- 一个会话的最后写入落在未覆盖日期、而它也在账本覆盖的日子里结算过时，会话数会重复计一次；账本的会话 id 与会话目录名不同格式，无法相减。
- 「高峰时段」只由折算补上的那几天决定：账本没有小时维度，它覆盖的日子在被折到之前没有直方图，窗口的峰值可能因此偏低。

## 重审条件

- 宿主发布跨会话的用量总量（不必再读别的插件的文件）时，改为只读宿主。
- 成本计量插件不再维护账本格式时，删掉这条路径。
