# D55. 重绘动效：过程按正式输出分段折叠

- **状态**：已实施
- **分组**：功能
- **关联**：D3、D9、D19、D26、D29、D32、D40、D41、D42、D44、D45

## 决定

- 新增功能 `chat-process`（`packages/client/src/features/chat-process/`，清单 id `chatProcess`，`load: 'deferred'`），挂在 `chatAnimations` 偏好的 `redraw` 档，与发送气泡动效同档并跑，对 `dsh-chat-ux` 让位（D32）。选到「增强」或「关闭」时整份卸下，过程区交还宿主。
- 不新建视图、不注册 `conversation.view`：与现有 chat-* 功能同构，观察宿主写出的 DOM 并就地改写。过程的每一行都是宿主自己渲染的流块，皮肤不搬动宿主的节点、不复制任何文本、不自己画一行过程：`data-turn-process-member` 是「这一行属于本轮的过程」的判据，本轮最终回答不是成员。皮肤自己只写一类节点——每一段的摘要行。重绘档与 dsh-better-display 不冲突：那个包接管的是视图槽位，本功能只读写宿主写出的属性。
- 折叠按正式输出分段，不按整轮：宿主把每个助手步骤拆成 `reasoning` 与 `response` 两行（`data-chat-group-part`），皮肤以每个 `response` 行结尾划出一段，一段就是「上一次正式输出之后、这一次正式输出之前」的那些过程行。一段的形式输出一到，这一段就收进它自己的摘要行；最后一段（还在写、或正是最终回答）保持展开。读者因此读到的是：思考与工具调用收在摘要行里，正式输出本身与其后的工作照旧展开。
- 摘要行是皮肤自己的节点：一行 `button`，`aria-label` 是这一段的数字（`思考×N · 工具×M · 记录×K`），可见部分是同样的字，数字各自用一个滚动格显示。数字变化时按 160 ms 跳变（旧值上移淡出、新值自下升入，曲线 `cubic-bezier(.16,1,.3,1)`），与 dsh-better-display 的 SubtleNumberRoll 同一配方。「动画」为「减弱」时数字直接写新值（D26）。读者按摘要行就把这一段重新展开，再按一次收回；他打开过的段在本轮剩下的时间里保持他选的样子。
- 折叠的标记落在行上，不落在分组上：皮肤给自己的段里每一行写 `data-segment-folded`，样式表把这行移出这一列（`display: none`），动画阶段先按行高收缩 320 ms 再写标记。宿主的一个过程分组可以同时装两段的行（一次 `response` 夹在分组之间），按分组折叠会把还在写的那一段一起收走。
- 整轮的开合跟随宿主：数量写在宿主自己的整轮控件上（`data-dsh-claude-process-counts`，值形如 ` · 思考×N · 工具×M · 记录×K`，空则不写），由样式表接在宿主标签之后、它自己的箭头之前（控件是 flex 行，伪元素取一个居中的 `order`），宿主标签、计时与无障碍名称都保持宿主的；计数按皮肤展示的行数算，不从宿主的两个数字（`data-turn-process-messages`、`data-turn-process-tool-calls`）借用——一个步骤不是一行，一次子调用也不是一条。宿主把整轮收起时（按层写 `hidden="until-found"`），皮肤先把自己的摘要行全部撤下，再按收缩、计数、停顿的时序让这一轮让位：收缩 320 ms、计数 160 ms、静止 80 ms，然后交还给宿主；读者重新打开整轮时按 180 ms 从零高度长回来。曲线 `cubic-bezier(.4,0,.2,1)`，用 WAAPI 直接动高度。每个相位都另有 240 ms 的兜底：被取消的动画会 reject、合成器没跑完的动画 promise 一直挂起、后台标签根本不给帧，没有这条线一段会停在非空闲相位里、把它的盒子一直按住。
- 整轮展开时，皮肤把这一轮摆成一列：每个过程组体由皮肤按宿主的控件打开、`data-dsh-claude-process-flat` 去掉它的高度上限与滚动条边距、组头 `data-dsh-claude-process-head` 让位给行、动画期间的行由 `data-dsh-claude-process-lane` 保持在位——组头被读者自己按过的那一组不碰，它的组头也留着，那是他回到该组的唯一入口。
- 思维行的自动滑动取 dsh-better-display 的 ReasoningCard 配方：还在写的思考行由皮肤找到它自己的滚动区，在区内插一层轨道，按「两行、停 840 ms」的阅读节奏走，积压多时一步追完（上限 40 行），曲线 `cubic-bezier(.22,1,.36,1)`，滑动由轨道上的合成transform承担。读者的滚轮、按下或选中把这一行交还给他：轨道当场拆掉，位置交给原生滚动，本轮剩下的时间里皮肤不再接管这一行的滚动。行不在页面上（整轮收着）时停在原地等它回来。「动画」为「减弱」时不驱动。
- 皮肤自己订阅 `hidden` 与 `aria-expanded` 的变化后请调度器排一次：读者开合一轮只改这两个属性，调度器自己的观察器带的是 `childList`、`characterData` 与另外两个 `aria` 属性，不带它们，少了这一条订阅皮肤只在内容流式到达时才跑（D40）。
- 滚动位置经滚动主人写（D41）：打开组体时宿主自己的 `focus()` 会滚动并抢焦点，两样都按原值还回去；窗口里读者原本在末尾时停在末尾。
- 契约：新读的宿主字面量是 `data-turn-process-member`（`process.member`）、`data-chat-group-part`（`chat.group-part`）与它的 `response` 取值（`chat.group-part-response`），工具计数与思考行计数用已有的 `chat.call`、`chat.think-row`，行身份用 `chat.flow-block`，另外声明 `chat.flow`、`chat.turn-attribute`、`chat.scroller`、`chat.follow-threshold`、`process.group`、`process.body`、`process.content`、`process.activity`、`turn.process`。皮肤自己写出的标记一律 `data-dsh-claude-` 前缀。
- 测试：`process-counts.test.ts` 覆盖计数、数字滚动与分段；冒烟用例 `chat-process` 用替身页面走完「分段折叠 → 摘要行上的数字 → 思维行自动滑动与交还 → 读者自己展开一段 → 读者自己收起一组 → 整轮收起 → 再打开」；端到端场景 `process`（`packages/testing/process-lane.cjs`）在真实宿主上核对数字、分段折叠与展开后的行；`packages/contracts/src/timing.ts` 的 `host.turn-process-fold` 记下「已完成的一轮按层写 `hidden="until-found"`」并「回合结束时重新认定成员行」这两条时序假设，由该场景持有。

## 理由

- 宿主本来就把过程里的每一行渲染成自己的流块，一行一条，也本来就按正式输出把一步拆成两行；皮肤只重排这一结构，就不必再写一套渲染，不会有两份文本、两份滚动与两份焦点顺序，宿主升级时按契约表一张单子审计（D3、D44）。
- 折叠停在正式输出上，读者读到的就是「工作 → 结果 → 工作 → 结果」这一条线：收起来的部分是这一段工作的记录，站着的是他此刻要读的正文。整轮收成一块时，中间那几段输出也跟着不见了，读者要在「全收」与「全开」之间二选一。
- 数字画在它描述的那一行上，读的时候不用在两行之间对；跳变而不是跳数，是因为这一段的行数在写作过程中不断变，直接换值会像错误刷新。
- 展开多少由读者自己的「工作步骤展示」决定：皮肤对「一轮该露出多少」没有立场，只决定露出来的那一部分长什么样。

## 代价

- 皮肤按宿主的过程结构与分段标记认行，宿主改一处结构就表现为列表收不拢、落回原布局；契约测试按 id 报出失配的那一条。
- 宿主在轮次结束时会重新认定哪些行属于过程（最终回答从成员里退出），皮肤按自己标过的行撤销折叠标记，而不是按当下的行重读——这段记账是本功能必须维护的状态。
- 组体是皮肤按宿主的控件打开的，宿主还在折叠时按下的一记会落空，因此同一组头会在停 400 ms 后再按一次（最多 12 次）；宿主的焦点与滚动位置由皮肤手工还回。
- 思维行的滑动在行内插了一层轨道并改它的 transform，正常交还时拆掉；读者中途接手由这一层立刻让位。

## 重审条件

- 宿主把过程区收成可依赖的公开组件、或给出重排扩展点时，改为依赖而不做 DOM 重排。
- dsh-better-display 把渲染层拆成可依赖的库并公开稳定接口时，改为依赖而不搬运时序与文案。
