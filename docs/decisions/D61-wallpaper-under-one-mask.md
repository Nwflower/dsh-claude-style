# D61. 壁纸插件在播壁纸时，Claude 配色在整个窗口铺一层底色遮罩

- **状态**：已实施
- **分组**：宿主边界
- **关联**：取代 D59；D3、D30、D31、D49、D51

## 决定

- 壁纸插件（`dsh-plugin-wallpaper-engine`）在 `body` 上挂 `data-we-wallpaper`，壁纸本体与它的暗化层、特效层是 `body` 的子节点，分别在 `z-index: -2` 与 `-1`；这个标记在即「有壁纸正在显示」。本插件只读这一个属性，它是别的插件的标记，不进 D3 的宿主契约表，读法写在用它的那几张表里。
- 标记在且配色为 Claude 时，`theme/wallpaper.css`（样式表顺序最后）做四件事：外壳让开——`body`、窗口框架、中栏、右栏、会话根节点（含会话滚动区的 `[data-phase]`）与侧栏不画底色，侧栏元素自己的 `--dsw-specific-sidebar-fill` 清成透明；一层遮罩——`body::after` 固定铺满窗口、`z-index: -1`，按文档顺序落在壁纸插件的各层之上、外壳之下，颜色是画布色，浅色 86% 不透明、深色 82%；输入区——座位本身、座位上方与会话顶部的两道渐隐不画，座位里垫一块与输入卡同宽的画布色托盘（卡片顶边以下到窗口底边），统计行与模型行落在它上面，滚过去的会话正文不会从卡片下方透出来；`tokens.css`、`typography.css`、`chrome.css` 里把画布刷到外壳上的规则挂 `:not([data-we-wallpaper])`，原有的配色门不动（D30）。
- `--dsw-alias-bg-base` 在 Claude 一档保持画布色，壁纸插件自己的清空被本插件的令牌块盖过：宿主用这个令牌画的面（设置窗口、各类浮层与卡片、引导层）照旧不透明。皮肤自己的面（弹层、账号弹层、搜索面板）同样不透明。
- 配色选「跟随宿主」时不铺遮罩，外壳与各面交给宿主与壁纸插件（D30）。

## 理由

- 一层均匀的遮罩让侧栏、标题区、会话与底部读数落在同一块底子上，对比度处处一致，壁纸作为整窗的淡色背景透出。
- 让位按元素列出，基础令牌留在画布色：宿主以后新增的面默认可读，需要透出壁纸的只有已知的那几块外壳。
- 输入区的托盘与卡片同色同宽，挡住滚到下面的正文，又不在整栏宽度上多出一条更亮的带子。

## 代价

- 壁纸只以约 14%（深色约 18%）的强度透出，遮罩比例写死，不随壁纸插件的暗化或玻璃滑条变化。
- 外壳让位按宿主的类名子串与属性列出；宿主给外壳换了元素或令牌，这几条要跟着改，失配由冒烟的 `host-palette` 用例发现。这个外来属性不在构建的属性检查之内（D51 只管 `data-dsh-*`）。

## 重审条件

- 宿主提供主题层级或令牌分层机制时，外壳的让位改由层来声明（与 D30 同一条件）。
- 壁纸插件提供公开的遮罩或可读性契约（例如由它画遮罩、本插件只给颜色）时，改用那份契约。
