# D3. 宿主选择器纪律

- **状态**：已实施
- **分组**：宿主边界
- **关联**：D19、D43、D44

## 决定

- 选择器在 `src/contracts/dom.ts` 定义一次，并在 `src/contracts/table.ts` 里有条目、在功能清单的 `contracts` 里登记（D44）；下面各条是挑选与写法上的纪律。
- 定位宿主元素按这个优先顺序：宿主的稳定契约（`[data-slot]` 插槽定位点、宿主自己的 `data-*` 属性，见 D19）→ 皮肤自己按结构写下的标记 → 带哈希类名的子串匹配。
- 宿主 CSS 模块的类名形如 `<哈希>_<局部名>`，子串匹配取最长的稳定片段，带上下划线：`[class*="_trailing"]`、`[class*="_row"]`。不带 `_` 的宽匹配只用于有意作用于全局的规则（全局字体、角标）。
- 新增子串选择器先在真实页面核对它匹配到的元素，确认没有误中。
- 不按界面文字匹配宿主元素；需要区分的宿主控件由皮肤按结构打标记（D19）。
- 不覆盖会话进行时 `[class*="viewArea"]` 的布局约定（`flex: 1 0 auto; min-height: auto`），它负责把输入框固定在滚动区底部。
- 全局链接颜色排除带 `_linkButton` 的链接：它们是自带文字颜色的填充或描边按钮（例如设置页的「充值」）。

## 理由

- 宿主类名里只有局部名稳定。
- 短片段与界面文字都出过实际问题：`row` 命中 `…_grow` 曾把输入框高度锁在 28px，`rail` 命中 `trailing`，`tag` 命中 `stage`；界面文字随语言与宿主版本变化。

## 代价

- 选择器更长；按结构写的标记要等皮肤的刷新写入（同一帧、绘制之前）。

## 重审条件

- 宿主为这些区域提供稳定的 `data-*` 契约时全面改读宿主的属性。
