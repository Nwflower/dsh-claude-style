# D44. 宿主契约模块与契约测试

- **状态**：部分实施（契约模块、条目表、清单依赖与构建检查已实施；契约测试与其余选择器、服务形状、时序假设待迁移）
- **关联**：承接 D3、D19 与 D32 的聊天区契约表；D42、D43、D45
- **现状**：契约模块是 `src/contracts/`：`dom.ts` 是皮肤依赖的宿主选择器与属性的唯一定义处（聊天区、外壳与核心这一批 65 条），`table.ts` 是每条 id、它是什么、谁在读，以及核对过的宿主构建；功能清单用 `contracts` 字段登记自己读过哪些条目，构建检查三者一致。其余选择器仍写在各功能里，服务形状仍写 `HostValue`，时序假设仍只在注释里；冒烟测试仍在一张按宿主结构手搭的替代页面上运行（`scripts/smoke/`）

## 决定

- 皮肤依赖的宿主选择器、属性、服务形状与时序假设集中成一个有类型的契约模块，每条注明在哪个宿主版本上验证过、哪些功能依赖它（功能清单里列出，D42）。
- 契约测试用锁定版本的真实宿主客户端包挂载真实组件来跑，逐条核对契约模块里的假设，取代手搭的替代页面。
- 宿主升级时先跑契约测试，失效的假设逐条列出，再改对应功能。
- 时序假设同样写成契约并测试，例如「宿主在挂上消息列时新建 ResizeObserver、在其中把位置写到最底」（D32）。

## 实施

- `src/contracts/dom.ts` 只放字面：皮肤读的每个宿主选择器与属性在这里定义一次。
- `src/contracts/table.ts` 是同一份契约的表：`id`、`value`（引用上面的字面）、`use`（它是什么、谁在读），表的头里写着这些条目核对过的宿主构建。表是构建与测试数据，不进产物；浏览器半边只带字面本身。
- 功能清单的 `contracts` 字段登记该功能读过的条目 id；构建检查：`dom.ts` 的每个字面在表里有条目、表里的 id 不重复、清单里的 id 都存在、每条要么被至少一个清单认领、要么标着 `owner: 'core'`（只由插件的核心与共享模块读的少数几条）。
- 迁移分步：本轮收进聊天区、外壳与核心这一批；其余散在各功能里的选择器按同一条路搬，搬完之前该功能的 `contracts` 只列已经收进来的条目。

## 理由

- 替代页面只能复现作者已经知道的结构，复现不了真实宿主的时序；聊天区跟随与宿主的争抢在替代页面上一直是绿的。
- 契约集中之后，宿主升级的影响面一眼可见。

## 代价

- 契约测试要能装上并挂载真实宿主包，环境比替代页面重；锁定的宿主版本要随支持范围更新。
- 加一条宿主选择器要同时改模块、表与清单三处，构建会盯着，但这三处是手工维护的。

## 重审条件

- 宿主为插件提供官方的契约或测试工具包时改用宿主的。
