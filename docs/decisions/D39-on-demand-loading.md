# D39. 按需加载：重的功能拆成单独的块

- **状态**：待实施（受上游阻塞）
- **分组**：构建与源码
- **关联**：D36、D42、D43
- **现状**：全部功能在一个产物里，页面加载时整份解析；宿主开放按需加载的入口（D43）之前不动

## 决定

- 设置页、对话导航、吉祥物、聊天气泡动效拆成单独的块，功能清单（D42）声明它们的按需入口，用到时再加载；首屏只解析主题与核心。
- 块的加载走 DSH 加载器的公开机制（资产 URL 与动态 import，D43 向上游争取）。

## 理由

- 产物未压缩约 1.6 MB，而首屏用得到的只是主题与少数常驻功能。

## 代价

- 第一次打开设置页、第一次演吉祥物时多一次加载；块与主产物之间的接口要稳定。

## 重审条件

- 加载器的公开机制迟迟没有、而主产物压缩后超过约 1 MiB 时，重新评估是否改用官方包在用的包内异步分包 `require.async`（目前没有给第三方插件的公开契约）。
