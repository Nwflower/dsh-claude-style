# D39. 按需加载：首屏用不到的功能拆成单独的块

- **状态**：已实施
- **分组**：构建与源码
- **关联**：D12、D36、D38、D42、D43、D49

## 决定

- 清单写 `load: 'deferred'` 的功能离开主产物：它自己的模块打成一个块，由宿主半边的资产路由按内容哈希提供（D38），页面被接管后立即请求，块到达后安装。块到达之前它的句柄不在 `ui` 上，读它的功能照常把它当作缺席。现在延后的有设置页、内容搜索、吉祥物、发送动效、对话导航、上下文弹层与封号彩蛋。
- 主产物携带的模块一律不复制进块：块对这些模块的导入保持为导入，运行时经 `virtual:dsh-claude-style/chunk-modules` 解析到主产物自己的实例，宿主包按加载器的 `require` 原样交出；两个块都会携带的模块并入主产物（`scripts/chunks.mjs`）。构建期生成的模块（`virtual:dsh-claude-style/generated`，D36）与源码模块同样处理：共享表按它们的 `virtual:` 路径给出主产物里的那一份，块不再带走第二份树摇结果。构建拒绝主产物与块同时携带一个模块，源码模块与生成模块都算在内，也拒绝块读取构建编号。
- 块与它的 source map 各自按自身内容的哈希命名（`chunkFiles`），由资产路由的一条路径送出（D38）：只改注释、不动代码时，map 换了名字，浏览器不会拿旧的那份。
- 块是经典脚本：运行时把工厂挂到自己的 script 元素上（`document.currentScript.__dshChunk`），`core/chunks.ts` 取下工厂、以共享表为 `require` 调用、拿到 `install`，脚本元素随即移除；同一代里同一个块只请求一次。
- 块装不上（加载失败、没有工厂、运行时抛错）等同于功能安装失败：报告一次并退役（D12）。块到达时这一代已经结束、页面已让给皮肤（设置页除外，D49）、功能已被关掉或已退役，就不安装。
- 样式表留在主产物：层叠顺序由全部样式表的统一序号决定（D42），块到达之前这些规则匹配不到元素。
- 只延后首屏可以缺席的功能：首屏就要改写宿主界面的（账号区、首页、输入区、模型与权限控件）留在主产物，否则页面先露出宿主原样再被改写。
- 构建的写入顺序是有意的：新资产先写、清单随后、清单里没有的文件最后删，`lib/client.js` 写在最后。页面跑着的客户端包一变就换代，而客户端热重载只认主产物：把主产物放到最后写，换代的那一代要的块已经在磁盘上、也已经在清单里，不会在新块落盘之前按旧清单请求块。
- 调试档 `DSH_CLAUDE_STYLE_DEBUG=1` 让清单继续带着上一代仍然存在的条目并保留它们的文件：宿主在启动时读到旧主产物的页面请求的是那一代的块名，名字还在清单里它才送得出去。发布构建不带这个标记，清单就是这一次构建自己的资产；持续集成里这个标记一律不生效。

## 理由

- 主产物在页面启动时整份求值；延后的功能在启动之后各自作为短任务求值与安装，启动阶段的主线程阻塞随之减少。本地临时宿主实测（两种产物各载入 20 次取中位数）：主产物 789 KB → 690 KB，前 3 秒的主线程长任务 713 ms → 648 ms，皮肤生效时刻 298 ms → 280 ms。
- 宿主加载器没有插件内的按需入口，也不接受外部 issue 与 PR（D43）；资产路由已经存在（D38），块走同一条路由与同一份清单，不需要新的宿主能力。

## 代价

- 延后的功能比主产物晚到一次请求（本地实测约 5 ms）；块到达之前打开设置页、按下搜索或点账号行没有反应。
- 宿主在启动时缓存客户端包：没有客户端热重载的宿主上，插件更新后页面拿到的仍是旧主产物，只有重启宿主才能换到新的；链接安装的开发机可以在重建时带上 `DSH_CLAUDE_STYLE_DEBUG=1`，让上一代的块继续可以送达。
- 构建要计算模块归属：主产物的模块集合与块的模块集合互相影响，反复计算到没有模块被携带两次为止。

## 重审条件

- DSH 加载器提供插件内的异步分块或资产 URL 时，块改走加载器的机制，删除共享表与经典脚本这层包装。
- 某个延后功能需要在首帧改写宿主界面时，把它移回主产物。
