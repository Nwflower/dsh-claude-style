# D43. 覆盖层定位与上游扩展点

- **状态**：待实施（向上游提交与等待）
- **分组**：宿主边界
- **关联**：取代 D2；D3、D19、D39、D41、D44
- **现状**：一切效果靠浏览器端的 CSS 覆盖与 DOM 覆盖实现，不修改 DSH 引擎、apiproxy 与官方 UI 包

## 决定

- 插件是盖在宿主上的一层：拿到宿主的正式扩展点之前，效果继续以 CSS 覆盖与 DOM 覆盖实现。
- 向上游提交扩展点，去掉最脆弱的几处覆盖：
  - 可替换的滚动跟随策略钩子（D41 与宿主争抢的根源）；
  - 输入框提交事件与回显气泡的生命周期事件（聊天气泡动效现在靠在捕获阶段抢先读草稿来判断提交）；
  - 吉祥物插槽（D24）；
  - 加载器支持资产 URL 与动态 import（D38、D39）；
  - 官方 UI 稳定的 `data-*` 属性，代替哈希类名的子串匹配（D3）。
- 每个扩展点合入后，对应的覆盖改为接入宿主，并从契约模块（D44）里删掉被取代的猜测。
- 宿主半边只做浏览器做不到的事：提供模型文案、字体、吉祥物帧图与其他资源、系统用户名、HDSL 契约、用量汇总、会话内容搜索、删除会话这些路由（D11、D22），以及设置表单用的 `Config`（D10）。

## 理由

- 覆盖层的正确性取决于宿主没有承诺过的内部细节；今天能做到的效果，宿主改一次版就可能失效，最有效的稳定手段是让宿主承诺。
- 主题仍是皮肤，宿主升级时要能快速跟进。

## 代价

- 上游的评审与发版节奏不受本仓库控制；等待期间两套写法（覆盖与接入）可能并存一段时间。

## 重审条件

- 宿主开放完整的主题 API 时，覆盖层整体迁移过去。
