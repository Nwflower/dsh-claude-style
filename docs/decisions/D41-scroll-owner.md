# D41. 聊天区的滚动位置只有一个写入者

- **状态**：已实施
- **分组**：运行时
- **关联**：D32、D34、D40、D43、D45

## 决定

- 聊天区的滚动位置只有 `packages/client/src/shared/scroll-owner.ts` 可以写：会话滚动条与过程组的滚动主体都由它写，每个滚动容器各自仲裁。滑行用 `packages/client/src/shared/scroll-ease.ts` 的弹簧，构建检查除滚动主人之外没有模块引用这条弹簧。
- 请求的来源与优先级，从高到低：
  - `jump`：对话导航滑到读者选中的一轮；
  - `fold`：过程组被皮肤自动展开后把位置放回原处，卷帘门落定后把跟随交还宿主；
  - `composer`：输入卡片变高时把停在底部的读者留在底部；
  - `follow`：增强跟随在结构变化时把跟随交还宿主；
  - `stream`：流式输出期间撤回宿主写到最底的那一下并滑过去，与 `follow` 同级；
  - `process`：封顶过程组主体的追赶。
- 读者自己的滚轮是浏览器的：滚动主人不接管这个事件，只把滚轮、触摸、指针按下、滚动键与页内查找记成「读者动过」，跟随与流式滑行的请求因此被拒绝。滚轮的减速曲线、触控板的惯性、边界处的表现都由平台自己画。
- 仲裁规则：
  - 容器上正在滑行的来源优先级更高时，请求被拒绝；同级或更高的请求照常执行，直接写入还会结束正在滑行的低优先级来源。
  - 读者接管一个容器后，`follow`、`stream`、`process` 的请求被拒绝，正在进行的滑行在下一帧结束；读者回到这个容器底部的阈值以内（会话 25px，过程组主体 4px），接管结束。结束由滚动事件当场判定，内容在读者回到底部之后才增长也不会留下接管。对话导航跳到某一轮时同样取一次接管（`holdReader`）：跳转是读者自己选定的阅读位置，跟随在这一期间让开。
  - 读者自己发出的消息（或宿主替它挂上的回显）到达后的 1.2 秒内，`stream` 的请求被拒绝、滑行结束，宿主把新消息滚进视野的那一下照旧一步到位。
  - 减少动态效果时，滑行请求直接写目标位置。
- 读者的滚动意图在 `packages/client/src/shared/reader-intent.ts` 判定。功能问「读者在某一时刻之后动过没有」用 `readerMovedSince`。
- 与宿主的交接只在这里发生：撤回宿主写到最底的那一下（`takeBackHostPin`）、在宿主的跟随关闭时滑到底或按它自己的「回到底部」按钮把跟随重新点亮（`handBackFollow`）、流式滑行期间把这个按钮藏起来（`holdFollowButton`）。
- 意图、滚动与消息到达的监听只在有功能加入（`joinScrollOwner`）期间挂着，最后一个功能离开时摘下。
- 仲裁、接管与释放、消息到达的让位、减少动态效果下的直接写入由单元测试（D45）在真实浏览器里核对。

## 理由

- 多个功能写同一个位置，跨功能的争抢只能逐个打补丁；一个写入者把争抢变成结构上不会发生的事。
- 插件只写自己要画的那几段路（跳转、跟随、过程组追赶），读者的滚轮路径不在其中：接管它就要连平台自己的减速曲线、触控板惯性与边界回弹一起换掉，而这几样在各平台上的表现本来就不一样。

## 代价

- 每个写滚动位置的功能都要先想清楚自己的来源与优先级；新增一个来源要同时改优先级表与单元测试。
- 读者滚动与插件画出来的滚动是两种运动：插件自己滑的那几段有它的速度上限与曲线，读者的滚轮是浏览器自己的减速。接管判定依赖位置（25px / 4px 阈值），长距离的插件滑行滚到两端时被夹在 0 与末尾之间。

## 重审条件

- 宿主开放可替换的滚动跟随策略（D43）时，跟随部分改为注册进宿主，这里只保留皮肤自己的跳转与过渡。
