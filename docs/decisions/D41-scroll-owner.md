# D41. 聊天区的滚动位置只有一个写入者

- **状态**：待实施
- **关联**：D32、D34、D40、D43
- **现状**：会话滚动条有四处写入：增强跟随（`chat-follow`）、卷帘门过渡（`chat-fold`）、对话导航（`turn-nav`）、输入卡片变高时把停在底部的读者留在底部（`composer`）；过程组跟随（`chat-follow/process-follow.ts`）写过程组自己的滚动主体。滑行共用 `src/shared/scroll-ease.ts` 的弹簧，写入时机与彼此的让位各自处理

## 决定

- 聊天区的滚动位置只有一个模块可以写：在 `scroll-ease.ts` 的弹簧之上扩展成滚动的唯一主人，管会话滚动条与过程组的滚动主体，每个滚动容器各自仲裁。跟随、跳转、过渡、输入卡片变高时的贴底、过程组跟随都向它提出请求（目标、优先级、是否可被打断），由它决定当前听谁的。
- 与宿主的交接只在这里发生：撤回宿主写到最底的那一下、在宿主的跟随关闭时把它重新点亮、隐藏与恢复宿主的「回到底部」按钮、读者自己发出的消息到达时让开。
- 读者的滚动意图（滚轮、触摸、指针按下滚动条、滚动键）由它统一判定，任何请求在读者接管期间都不执行。
- 减少动态效果时它直接写目标位置，不滑行。

## 理由

- 多个功能写同一个位置，跨功能的争抢只能逐个打补丁；一个写入者把争抢变成结构上不会发生的事。

## 代价

- 现有五处写入要改成请求；仲裁规则（谁能打断谁）要显式写下并测试。

## 重审条件

- 宿主开放可替换的滚动跟随策略（D43）时，跟随部分改为注册进宿主，这里只保留皮肤自己的跳转与过渡。
