# D41. 聊天区的滚动位置只有一个写入者

- **状态**：已实施
- **分组**：运行时
- **关联**：D32、D34、D40、D43、D45

## 决定

- 聊天区的滚动位置只有 `packages/client/src/shared/scroll-owner.ts` 可以写：会话滚动条与过程组的滚动主体都由它写，每个滚动容器各自仲裁。滑行用 `packages/client/src/shared/scroll-ease.ts` 的弹簧，构建检查除滚动主人之外没有模块引用这条弹簧。
- 请求的来源与优先级，从高到低：
  - `jump`：对话导航滑到读者选中的一轮；
  - `fold`：过程组被皮肤自动展开后把位置放回原处，卷帘门落定后把跟随交还宿主；
  - `wheel`：读者自己的滚轮，距离交给弹簧走完；
  - `composer`：输入卡片变高时把停在底部的读者留在底部；
  - `follow`：增强跟随在结构变化时把跟随交还宿主；
  - `stream`：流式输出期间撤回宿主写到最底的那一下并滑过去，与 `follow` 同级；
  - `process`：封顶过程组主体的追赶。
- 滚轮由这里接管：监听挂在会话滚动条自己身上（非 passive，只有这一个），`preventDefault` 之后把这一格的像素距离累加到一个目标上，交给弹簧；目标每帧重读，所以第二格只是把滑行延长，不重新起跑；一段长距离整段滑完（不受 1200px 的 lead 截断）。以下情况一律不接管、交回浏览器：Apple 平台（桌面外壳写的 `data-platform="darwin"`，或浏览器自己的平台串是 Mac / iPad —— 那边的滚动本来就带惯性与边缘回弹，弹簧只会把原有的表现换掉），指针与滚动条之间还有能朝这个方向滚动的嵌套滚动条（过程组主体、diff、代码块），`Ctrl` 按着（缩放），读者的动效选择是「关闭」，已经有人 `preventDefault`，以及内容还不足一屏。监听挂在元素而非 `document` 上，是为了让页面其它地方的滚轮不必等主线程。
- 仲裁规则：
  - 容器上正在滑行的来源优先级更高时，请求被拒绝；同级或更高的请求照常执行，直接写入还会结束正在滑行的低优先级来源。
  - 读者接管一个容器后，`follow`、`stream`、`process` 的请求被拒绝，正在进行的滑行在下一帧结束；读者回到这个容器底部的阈值以内（会话 25px，过程组主体 4px），接管结束。结束由滚动事件当场判定，内容在读者回到底部之后才增长也不会留下接管。
  - 读者自己发出的消息（或宿主替它挂上的回显）到达后的 1.2 秒内，`stream` 的请求被拒绝、滑行结束，宿主把新消息滚进视野的那一下照旧一步到位。滚轮不受这条约束：读者自己的滚动任何时候都算数。
  - 减少动态效果时，滑行请求直接写目标位置，滚轮整条路径让给浏览器。
- 读者的滚动意图只在这里判定：滚轮、触摸、指针按下、滚动键与页内查找，判定规则在 `packages/client/src/shared/reader-intent.ts`。指针按在过程组主体的内容上是在展开某一行，只有按在主体自己（滚动条）上才算接管这个主体。功能问「读者在某一时刻之后动过没有」用 `readerMovedSince`。
- 与宿主的交接只在这里发生：撤回宿主写到最底的那一下（`takeBackHostPin`）、在宿主的跟随关闭时滑到底或按它自己的「回到底部」按钮把跟随重新点亮（`handBackFollow`）、流式滑行期间把这个按钮藏起来（`holdFollowButton`）。
- 意图、滚动与消息到达的监听只在有功能加入（`joinScrollOwner`）期间挂着，最后一个功能离开时摘下；滚轮监听跟着会话滚动条走，会话切换换了元素就重新挂。
- 仲裁、接管与释放、消息到达的让位、减少动态效果下的直接写入、滚轮的接管与滑行由单元测试（D45）在真实浏览器里核对。

## 理由

- 多个功能写同一个位置，跨功能的争抢只能逐个打补丁；一个写入者把争抢变成结构上不会发生的事。
- 读者自己的滚轮如果由浏览器写，落地的那一下和插件画的滑行不是同一种运动：一串滚轮格把整段距离压在一帧里，触控板的惯性还会和跟随打架。交给同一条弹簧之后，读者滚动与插件滚动是同一种运动，速度有上限，第二格接着上一段走。接管只发生在原本没有这条曲线的地方（Windows 与其他非 Apple 平台：滚轮在边界处直接停住、没有惯性收尾）；Apple 平台上平台自己就把这段路画好了，交给它反而更一致。

## 代价

- 每个写滚动位置的功能都要先想清楚自己的来源与优先级；新增一个来源要同时改优先级表与单元测试。
- 滚轮这一段（Apple 平台以外）是插件自己实现的滚动：长距离的滑行有插件自己的速度上限，曲线是弹簧而不是浏览器自己的减速曲线，滚到两端位置被夹在 0 与末尾之间、没有回弹（Windows 的 Chromium 本来就没有边缘回弹，只有 Android 有边缘光晕）。触屏拖动走 touch 事件，不经过这里；嵌套滚动条滚到尽头交给浏览器衔接，那一下是浏览器自己的滚动。macOS 与 iPadOS 上完全不接管，那边的惯性曲线与边缘回弹照旧由平台画。

## 重审条件

- 宿主开放可替换的滚动跟随策略（D43）时，跟随部分改为注册进宿主，这里只保留皮肤自己的跳转与过渡。
