# D9. 样式性能：结构判断写成属性，`:has()` 只放在最后一段

- **状态**：已实施
- **分组**：构建与源码
- **关联**：D40、D51

## 决定

- 依赖 DOM 结构的判断由脚本算好、写成属性，样式只读属性：输入框形态 `data-composer-variant`、附件 `data-dsh-claude-attachment`、草稿为空 `data-dsh-claude-draft-empty`、控件 `data-dsh-claude-control`（D19）、视图标签条 `data-dsh-view-tabs`。
- `:has()` 只出现在选择器的最后一段（`A:has(B)`、`A :has(B)`），后面不接后代或兄弟选择器（`A:has(B) C`、`body:not(:has(B)) C` 都不允许）；构建在语法树上逐层检查，拒绝违规写法（D51）。
- 每帧都要问的页面问题读一次就留下来复用：会话的滚动容器与消息列（`packages/client/src/shared/chat-dom.ts`）在元素仍留在文档里时不再重新查找，元素被移除（换会话、切「轨迹」页签）后才重新读取；流式标记在消息列内查找，宿主「回到底部」按钮的存在本身就是「跟随已关闭」的判据；同一帧里读到的高度只读一次，交给同帧的其余判断与滑行终点共用（`scroll-owner.ts` 的 `takeBackHostPin`、`scroll-ease.ts` 的终点）。

## 理由

- 在无界面 Chrome 里打开会话、每帧追加一个字（等同流式输出）实测：违规写法单条让每帧样式重算多出 7–13ms，与括号里测的是结构还是 `:hover` / `:focus-within` 无关；位于最后一段的每条只有 0.1–0.5ms。
- 全部改完后，整张样式表下每帧样式重算 1.9–2.7ms（不加载样式表时 1.4ms），主线程每帧总耗时 5–7ms。
- 长会话里流式输出时，跟随在每一批文字到达时问一次页面，那批文字刚把样式写脏，这一次查询就换来一次整页样式重算。临时会话（120 轮、4286 个节点）实测：把这几处查询与同一帧里重复的读数去掉后，插件发出的文档级查询从 3263 次降到 2762 次（−15%），整页最长一次停顿从 270ms 降到 234ms；文档越大，省下的每次重算越贵。

## 代价

- 结构状态要等脚本写入（同一帧、绘制之前）。

## 重审条件

- 浏览器对非末段 `:has()` 的失效处理实测不再明显慢于末段写法。
