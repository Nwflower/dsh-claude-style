# D40. 观察总线与帧管线

- **状态**：已实施
- **分组**：运行时
- **关联**：取代 D6；D12、D32、D41、D42、D45

## 决定

- 页面上只有一个 MutationObserver（`packages/client/src/core/bus.ts` 的 `subscribeMutations`）。订阅写明目标与 MutationObserver 自己的选项（子节点、属性及其名单、字符数据、是否含子树），总线把同一目标上各订阅的选项合并后挂上，每批记录再按每个订阅自己的选项分回去：一个订阅收到的正好是它自己的选项选中的记录，回调按订阅建立的先后执行。订阅增删时总线重挂，旧挂载已收集的记录照样交给订阅者；没有订阅时整个观察者摘下，所以 `<head>` 只在有人订阅时被观察。
- 尺寸由 `observeSize` 统一登记：一个订阅可以同时看几个元素，每批尺寸变化只回调一次、只带它自己的元素。普通订阅共用一个早建的 ResizeObserver；`afterHost` 的订阅共用另一个，每加入一个订阅就重建一次。浏览器按建立先后调用 ResizeObserver，宿主在挂上消息列时新建自己的，所以在新消息列出现之后订阅的 `afterHost` 回调排在宿主之后（D32 的跟随在宿主写到最底的同一帧里把位置收回）。
- 帧管线（`packages/client/src/core/frame.ts` 的 `requestFrame`）：皮肤的每个帧回调都经它，整页只有一个 `requestAnimationFrame`。每帧先依次运行所有任务的读阶段，再依次运行写阶段；写阶段也可以读，读到的是本帧在它之前写下的结果。帧内请求的任务属于下一帧，帧内取消的任务不再运行剩下的阶段。刷新、聊天区跟随、插入符、开合、淡入、气泡动效、滚动弹簧、对话导航与各处「等一帧」都在写阶段运行。
- 订阅、尺寸登记与帧任务出错时用 `reportError` 报告，其余照常（D12）。
- 必须继续满足的行为：
  - 带 `data-dsh-claude-quiet` 的皮肤记账节点：刷新的订阅设 `skipQuiet`，容器内部的改动与增删带此标记的节点不算页面变化。
  - 指针移动只经 `onActivity` 告诉功能「读者在」，只记时刻，不触发刷新。
  - 皮肤代发给宿主菜单的 Escape 带 `__dshHostMenuEscape`，全局键盘路径见到就跳过。
  - 系统「减少动态效果」中途翻转、或另一个聊天插件装卸，都重解动画档位并重跑偏好监听（`refreshMotionAttribute()`、`notifyEnvironmentChange()`），功能不各自听媒体查询。
  - 文本选区、主题翻转、分段控件尺寸、皮肤中心的归属标记这些监听各是总线上自己的订阅，不触发刷新。
  - 弹层开着期间的指针与按键在打开时挂、关闭或卸载时摘。
  - 每个订阅只在值变化时写 DOM（同值写入也会让元素样式失效）。
- 订阅随功能的安装与卸载成对增删；总线与帧管线的分发顺序、选项路由、早晚两个尺寸观察者的先后由单元测试（D45）在真实浏览器里核对。

## 理由

- 各功能自带观察者时，先后顺序只能碰运气：D32 的跟随与宿主互相争抢滚动位置，就是两个 ResizeObserver 谁先建立的问题。
- 一个注册表让顺序成为可声明、可测试的东西；读写分阶段让多个功能在同一帧里不互相触发强制布局。

## 代价

- 总线成为所有功能的公共依赖，它出错影响面大，需要最完整的单元测试。
- 选项合并后，浏览器替每个订阅做的筛选改由总线在脚本里做：同一批记录要按订阅逐条判定。
- 几个功能的帧回调既读又写，目前都放在写阶段；拆成读写两半要逐个确认它读的是不是自己或别人本帧刚写的结果。

## 重审条件

- 宿主提供统一的页面变化订阅或渲染阶段钩子时，总线改为接入宿主的。
