# D40. 观察总线与帧管线

- **状态**：待实施
- **关联**：取代 D6；D41、D42
- **现状**：`src/core/scheduler.js` 持有一个观察 `<body>` 整棵子树的 MutationObserver（子节点、字符数据，属性只看 `aria-label` / `aria-selected`），把变化合并成每帧一次刷新、按顺序调用各功能的 `sync()`；搬来的聊天区交互、分段控件、对上游的 `<head>` 观察等各自持有 MutationObserver、ResizeObserver 与监听

## 决定

- 页面上只保留一个 MutationObserver 与一个 ResizeObserver 注册表。功能按选择器与关心的变化类别（子节点、属性及其名单、字符数据、尺寸）订阅，由总线统一分发。
- 总线保证调用顺序，包括「排在宿主之后」：宿主在挂上消息列时新建自己的 ResizeObserver，浏览器按建立先后调用回调，所以凡是要在宿主之后读写的订阅，总线在新消息列出现时为它们重建观察者（D32 的跟随就是这种）。
- 每帧分读、写两个阶段：所有功能先在读阶段量尺寸，再在写阶段改样式与属性，消除来回强制布局；零散的 `requestAnimationFrame` 都并进这条管线。
- 必须继续满足的行为：
  - 带 `data-dsh-claude-quiet` 的皮肤记账节点：容器内部的改动与增删带此标记的节点不算页面变化（否则插入符动效每帧建测量探针，读者每敲一个字都触发一轮刷新）。
  - 指针移动只经 `onActivity` 告诉功能「读者在」，只记时刻，不触发刷新。
  - 皮肤代发给宿主菜单的 Escape 带 `__dshHostMenuEscape`，全局键盘路径见到就跳过。
  - 系统「减少动态效果」中途翻转、或另一个聊天插件装卸，都重解动画档位并重跑偏好监听（`refreshMotionAttribute()`、`notifyEnvironmentChange()`），功能不各自听媒体查询。
  - 对 `<head>` 子节点的观察只在有订阅者时挂（另一个聊天插件装卸只改 `<head>` 里的一个 `<style>`；D33 的外来样式表标记也在这里执行）。
  - 弹层开着期间的指针与按键在打开时挂、关闭或卸载时摘；文本选区、主题翻转、分段控件尺寸这类不得喂进刷新的监听，由总线以独立通道分发，不触发全体刷新。
  - 每个订阅只在值变化时写 DOM（同值写入也会让元素样式失效）。
- 订阅随功能的安装与卸载成对增删，测试核对卸载后不留监听与标记。

## 理由

- 各功能自带观察者时，先后顺序只能碰运气：D32 的跟随与宿主互相争抢滚动位置，就是两个 ResizeObserver 谁先建立的问题。
- 一个注册表让顺序成为可声明、可测试的东西；读写分阶段让多个功能在同一帧里不互相触发强制布局。

## 代价

- 总线成为所有功能的公共依赖，它出错影响面大，需要最完整的单元测试。
- 功能的观察需求要表达成订阅声明，有一次性的改写成本。

## 重审条件

- 宿主提供统一的页面变化订阅或渲染阶段钩子时，总线改为接入宿主的。
