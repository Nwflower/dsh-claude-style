# D37. CSS 工具链：层叠层、作用域插件、样式检查与设计令牌

- **状态**：待实施
- **关联**：承接 D4、D9、D30；D36、D49
- **现状**：样式表按 `STYLE_FILES` 的顺序拼接，靠拼接先后与 `!important` 决定优先级；作用域前缀由作者手写，没有检查；输入框门控、`:has()` 位置、配色与字体门由 `scripts/build.mjs` 按字面检查

## 决定

- 用 `@layer theme, features, overrides` 排定层叠顺序，替代大面积的 `!important` 与拼接先后。共用部件的规则在 `theme` 层，功能的规则在 `features` 层；必须压过宿主内联样式的少数规则才进 `overrides`，并写明原因。
- 作用域：每条规则挂在 `body[data-dsh-claude-style]` 下，由 CSS 构建插件（PostCSS 或 Lightning CSS）统一加前缀，源码里不再手写；暗色令牌为基准，亮色覆盖写在 `:not([data-ds-dark-theme])` 下。
- 输入框门控（D4）由同一个构建插件盖章并检查。
- Stylelint 规则：`:has()` 只在最后一段（D9）；写宿主颜色令牌的规则挂配色门、写字体令牌的规则挂字体门（D30）；功能样式表里画面的颜色只读令牌。
- 设计令牌改为一份 JSON，生成两个品牌、亮暗两套主题的自定义属性，以及宿主一档的别名表（D30）；`docs/STYLE.md` 里的令牌表也从这份文件生成。

## 理由

- 拼接先后与 `!important` 决定优先级，加一张样式表就可能改变别处的结果；层叠层让优先级成为声明出来的东西。
- 作用域、门控、令牌门都是机械规则，交给工具执行，作者与审阅者不必再记。

## 代价

- 引入 CSS 构建插件与 Stylelint；全部样式表迁移一次，迁移时逐条核对 `!important` 的去留。
- 生成的令牌文件与 STYLE.md 令牌表不能手改。

## 重审条件

- 宿主提供主题层级或令牌分层机制时，令牌改为接入宿主的层级。
