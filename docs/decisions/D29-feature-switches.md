# D29. 功能开关：每个功能声明开关或不设开关的理由

- **状态**：已实施
- **关联**：D12、D42

## 决定

- 每个功能在自己的清单（D42）里二选一地声明 `pref: '<偏好键>'` 或 `ungated: '<理由>'`；两个都写由类型拒绝，两个都没写或 `pref` 不是宿主半边 `PREFS_DEFAULT` 里的键由构建拒绝。
- 划分标准：替换或挪动宿主原有的控件与区域、或往界面上加新的可见元素的功能设开关；不设开关的是只修宿主毛病而不改变功能的（`selection`、`themeFlip`）、从属于另一个已有开关的（`copy` 与 `heroMenu` 跟随输入框改造的范围，`effort` 跟随模型选择器，`quickProviders` 是模型选择器的设置项）、只在点击时出现的（`ban`）以及设置页本身。两个功能可以共用一个开关：`contextStats`（D27）与 `permissions` 都声明 `permissionsControl`。
- `pref` 属于 `FEATURE_PREF_DEFAULTS`（全部默认开）时统一执行：启动时关着的功能不安装；偏好每次被采用时逐个对照，关掉就运行它自己的 teardown、删掉句柄、交还接管的宿主界面，打开就重新安装，都不刷新页面。其余的 `pref`（`composerScope`、`homeLayout`、`modelPicker`、`collapseFooter`、`mascot`）由功能自己读。退役过的功能（D12）在本代内不因偏好变化装回。
- 设置页按分页组织（通用、外观、输入区、侧栏、对话）。布尔开关的行由拥有这个偏好的功能在清单里声明（分页、序号、标题与说明的文案键），共用一个开关的几个功能只由其中一个声明；其余的行写在 `src/features/settings/settings-tab-*.ts`，控件在 `settings-controls.ts`，两者按序号合并；从属于另一项的行紧跟在它下面、两行之间不画分隔线，父项关闭时变灰、不能操作。

## 理由

- 新功能登记时就要回答「读者能不能关掉它」；开关的语义统一为「关掉 = 宿主原样」，每个功能的 teardown 本来就负责交还宿主界面（D12），开关只是在运行中调用它。

## 代价

- 每个功能的 teardown 必须能在运行中途执行并完整交还宿主界面，测试逐项核对开关打开与关闭两种状态。

## 重审条件

- 宿主提供插件级的功能开关或按区域停用插件的机制时，改接宿主的。
