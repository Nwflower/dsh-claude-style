# D32. 搬来的聊天区交互：自己的前缀、自己的偏好、对上游让位

- **状态**：已实施
- **分组**：功能
- **关联**：D26、D29、D40、D41、D44
- **迁移**：聊天区契约表并入契约模块（D44，待实施）

## 决定

- 从 dsh-chat-ux 搬入的聊天区交互（token 淡入、思考行与过程组自动开合、卷帘门过渡、增强跟随、组体跟随、文件变更行、插入符动效、聊天气泡动效、过程组标题上的计数、说明模型正在做什么的那一行）分目录放在 `chat-follow`、`chat-fold`、`chat-reveal`、`chat-files`、`chat-send`、`chat-wait`、`caret`。推理期间思考行里的回放窗口来自 transitions.dev 的「Reasoning stream」（`chat-fold` 的 `reasoning-stream`，裁剪的是宿主自己那个推理正文槽位），与状态行文字交替、计数数字滚动一样属于搬来的动效。
- 它们只读宿主自己写的属性；聊天区的整份宿主契约（流式容器、工具调用行、过程组、思考行的推理正文槽位、会话滚动条、输入框与回显气泡等）集中在 `packages/contracts/src/dom.ts` 一张表里。
- 功能自己写出的标记（DOM 标记、类名、`::highlight()` 名称、自定义属性、关键帧名称）一律用 `data-dsh-claude-` 前缀，与上游包同时装着时两套实现读不到对方的状态。
- 不止读标记的三处：
  - 文件变更行接管宿主 `tool.call.toolview` 座位上的 `edit` 与 `write` 两个键位（优先级 -1，低于宿主自己那两个），改动派生与宿主的卡片模型只差「不排除子调用」这一条。
  - 聊天气泡动效在 `<body>` 末尾挂一个临时替身，带 `inert` 与 `aria-hidden`，摘掉身份标记但保留样式钩子；飞行期间给真实那一行写标记把它藏起来（保留布局盒），到达后真实行先显示、替身淡出。
  - 增强跟随在流式输出期间接管会话滚动条的跟随：宿主每次内容增长都把位置写到最底，跟随在同一帧绘制之前把这次位移撤回、交给滚动主人（D41）滑过去。宿主写这一下的地方是它挂上消息列时新建的 ResizeObserver（观察消息列、会话滚动条、输入框座位），浏览器按建立先后调用回调，所以跟随的观察者每遇到一条新的消息列就重建一次，排在宿主之后、观察同样三个元素。跟随期间把宿主自己的「回到底部」按钮临时藏起来（只写自己的标记，宿主的状态不动）；读者自己发出的消息到达时跟随让开一段，宿主把新消息滚进视野的那一下照旧一步到位。
- 设置：这些功能共用皮肤自己的偏好条目与设置页，不动上游 `dsh-chat-ux` 的配置。对话区各项共用一个开关 `chatAnimations`（「聊天区动画效果」）：开启时安装，关闭时这些功能一起卸载、各自把界面交还宿主。各功能的清单用 `pref` 声明自己挂在哪个偏好上，用 `prefValues` 声明一项选择偏好下自己运行的取值（D42）；插入符动效是自己的三选一（`caretMotion`）。随偏好出现的样式规则由功能把标记写到 `<body>` 上（如 `data-dsh-claude-chat-follow`）。
- 对上游让位：页面装着上游时这些功能整体让位（`packages/client/src/shared/peer-plugin.ts` 读宿主启动图里的条目，也读上游留下的样式表节点）；设置页把两行控件禁用、保留读者的值，下面以强调色写明由谁接管。让位由清单的 `yieldsTo` 声明（D42），入口统一执行：上游在页面上时这些功能不安装，上游中途装卸会立刻卸下或装回（`<head>` 的观察重跑偏好监听），功能内部不再自己判断。
- 动画效果读 `motionReduced()`（D26），样式表一侧以 `<body>` 上的动画属性为门控。
- 没有搬的一处：上游会把网页端「工作步骤展示」的缺省档位补成「标准」。本仓库不代写宿主 `ui-chat` 的设置；网页端默认档位（「详细」）下组体不封顶，自动开合与组体跟随在那两处不发生，读者选到「标准」或「简洁」后生效，README 写明这一点。

## 理由

- 上游的属性名原样保留时，两套实现同时装着会互相认领对方的标记；只换前缀不足以共存——两套卷帘门会互相回放同一次点击，两套自动开合各点同一个开关，文件变更行两边同优先级注册同一键位会抛错，所以必须整体让位。
- 跟随的观察者若在安装时建好一直沿用，就排在宿主之前：宿主那一下每帧都画出来，下一批文字到达时跟随又把已经画出来的位置拉回去，画面忽而上跳、忽而下掉。

## 代价

- 上游的更新要人工对照搬运；行为由本仓库自己的测试覆盖，包括一个上游在场的让位用例。

## 重审条件

- 上游把这几项拆成可依赖的库并公开稳定接口，或宿主自己把这些交互收成正式能力时，改为依赖而不搬运。
