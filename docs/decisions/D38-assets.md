# D38. 资源只有一条路径：内容哈希清单与通用资产路由

- **状态**：已实施
- **分组**：构建与源码
- **关联**：承接 D24 的帧图、D36 的构建；D11、D12、D39、D46

## 决定

- 图片与图形资源都在 `packages/assets/src/` 下，构建（`packages/assets/assets.mjs`）为每个文件算出内容哈希（sha256 前 12 位），并由文件自己的字节数决定交付方式：不超过阈值的（16 KiB）内联进产物——图片写成数据地址，厂商组合标写成标记文本，因为选择器用 `innerHTML` 把它盖进行里，好让单色层继承那一行的颜色；超过阈值的写到 `lib/assets/<哈希>.<扩展名>`，由宿主半边一条通用路由 `/dsh-claude-style/assets/<哈希>.<扩展名>` 提供。
- 路由只认清单里出现过的名字：构建把清单写在 `lib/assets/manifest.json`，请求名必须命中它，因此资源目录之外什么都读不到。名字里带着内容哈希，可以长期缓存；文本资源按 brotli 预压缩存放，不接受 brotli 的客户端由路由解压后送出。延后功能的块与它的 source map（D39）也登记在这份清单里、由同一条路由提供，总是走路由，各自的名字取自身内容的哈希。
- 帧图与动画登记表的对应关系、帧数、裁切框、静止帧的合法性在生成清单时检查，另外核对表图自己的像素：裁切框必须整除表图，格子数必须装得下登记的帧数。没有任何登记认领的资源构建失败。
- Deepy 的帧图在构建期转成矢量（`vectorizeSheet`）：按裁切框把每帧摆成一格、四周留 `DEEPY_GUTTER` 个逻辑像素的透明边，逐行取同色游程，把同列同宽的同色游程向下并成矩形，每种颜色一条 path。产出的 SVG 就是浏览器播放的图形；表图 PNG 只作为构建的输入，不进 `lib/`。
- 浏览器端的画布转换、Cache API 缓存与两处相关的 catch 随之删除（D12）；运行时只剩一次图片加载。

## 理由

- 两条交付路径各自合理，但每加一种资源都要先判断走哪一条；路径的选择应该由大小自动决定。
- 浏览器端重建矢量的唯一目的是播放矢量图；构建时做完，运行时只剩加载。
- 实测 18 张表：PNG 原图共 426 KB，构建期转出的矢量未压缩 3.4 MB、brotli 后 658 KB（每张 12–66 KB）。同样格子布局的补边 PNG 是 1.27 MB，而直接送未补边的 PNG 会退回缩小取样越过帧格边界画出的灰线；矢量比补边 PNG 小一半，观感与之前播放的完全一致。

## 代价

- 宿主半边多一条通用路由；更新插件后没有重启宿主时，旧的宿主半边没有这条路由，矢量读不到（对应的动画缺席，控制台说一次）。
- 构建多一步矢量化与压缩；随包携带的帧图从 426 KB 增到 658 KB。

## 重审条件

- DSH 加载器支持资产 URL 时，资源改随客户端包分发；块随 D39 的重审条件改走加载器之后，删除这条路由。
