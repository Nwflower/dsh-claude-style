# D12. 快速失败与功能隔离

- **状态**：已实施
- **分组**：运行时
- **关联**：D29、D38、D42

## 决定

- 出错的地方直接抛出，不吞错误、不静默回退。宿主服务可能缺席时，用可选链与 `typeof` 表达「没有这个服务」，不用 try/catch；宿主服务是否存在以 `ctx.get` 的返回值判断（cordis 对缺席的服务返回 `undefined`）。可选的文件（读者放进来的字体、HDSL 头像、尚未建立的会话根目录）用 `existsSync` 或 `statSync(…, { throwIfNoEntry: false })` 判断。
- 功能隔离：teardown 最先注册且幂等；每个功能单独安装，装不上的报告一次并退役；每轮刷新里每个功能单独执行，连续失败 3 轮即报告并退役。刷新机制自身装不上时整体回到宿主原样。
- 退役就是运行这个功能自己的 teardown，交还它接管的宿主界面：页脚接管与输入框重绘的门控强制关闭；权限控件替换的宿主控件由它自己的标记把守、随它的 teardown 交还。每个功能的 teardown 是它的 DOM 与标记的唯一清理。
- 需要隔离、但错误必须可见的地方用 `reportError`：`notifyAll` 逐个通知监听函数，观察总线逐个通知订阅、帧管线逐个运行任务（D40），某个出错就报告、其余照常；卸载时单个功能失败报告后继续；功能开关（D29）关闭某个功能时它的 teardown 抛错，同样报告，这个功能在本代内不再装回。
- 浏览器半边允许的 catch，每处写明原因：
  - 上述隔离。
  - 宿主以抛错表达的预期状态：设置表单的 `set()` 拒绝不属于该配置的字段；`modelDirectories.directoryFor` 对还没建立的会话抛错，下一轮重试；`sessionQuery.readSession` 以 `SESSION_QUERY_CORRUPT_SESSION` / `SESSION_QUERY_SESSION_NOT_FOUND` 表示某个存档读不了或已被删，内容搜索与用量汇总把这一个会话记为空并记一条警告。
  - 文件变更行解析流式工具的原始参数：参数逐块到达，半截 JSON 是正常的中途状态，解析不了就交回宿主的输入 / 输出卡片（`features/chat-files/file-row-model.ts`）。
  - 阅读视图的错误边界（`features/chat-reader/blocks.tsx` 的 `BlockBoundary`，D57）：一个块或一行渲染失败，只把这一处换成一行说明并用 `reportError` 报告，会话的其余部分照常渲染。
  - Promise 上表示「宿主半边没有应答」或「宿主自己会提示」的失败回调。
- 宿主半边允许的 catch，每处写明原因：
  - `webServer.register` 以抛错拒绝已被别的插件占用的路径：逐条注册，被拒的记警告，其余照常（宿主半边的纤程失败会连带撤下浏览器半边的整个包）。
  - 卸载时逐个运行路由的撤销函数，单个失败记警告后继续。
  - 删除会话的请求体不是 JSON 时答 400；删除过程中的任何故障答 500 并带错误信息。
  - 宿主半边 `lib/assets/manifest.json` 读不了或不是 JSON 时答 404：那是构建没跑完的状态，记一次警告即可，不必让路由本身失败。
  - 成本计量插件的账本是别的插件的文件，读取与它的写入没有协调，解析不了时当作没有账本、改用本地折算。
  - 用量汇总自己的缓存只省工作量：读不了时记警告并整体重算覆盖，写不进时记警告、本轮结果照常返回。

## 理由

- 被吞掉的错误会在别处以更难排查的方式出现；隔离只负责不让一个功能拖垮其他功能，失败本身必须留下记录。

## 代价

- 功能失效时界面上没有提示，只有控制台记录；依赖同一宿主服务的功能会一起退役。

## 重审条件

- 宿主提供插件级的错误上报时，把报告接过去。
