# D42. 功能清单

- **状态**：待实施
- **关联**：取代 D13；承接 D29；D12、D39、D40、D44、D48
- **现状**：`src/entry.ts` 的 FEATURES 表（`{ name, handle?, pref | ungated, install }`）决定安装与刷新顺序；功能拆出的部分写成以功能名开头的顶层工厂 `createX(...)`；设置页的开关、冒烟测试的功能覆盖表、对上游的让位各自维护

## 决定

- 每个功能导出一份清单：`id`、偏好键或不设开关的理由（D29）、依赖的宿主契约（D44）、样式表、安装函数、按需加载入口（D39）、它向观察总线（D40）与滚动主人（D41）登记的订阅与请求、中英文的功能描述。
- 安装顺序、设置页的开关行、测试的覆盖表、对上游的让位、README 的功能介绍（D48）都从清单汇总生成，不再各写一份。
- 功能句柄可实现的钩子：`sync`、`owns` + `close('outside')`、`onPointerDown`、`close('escape')`、`close('composer')`、`onInput`、`onFocusIn`、`reposition('viewport' | 'composer')`、`onCopyChange`、`onKey`、`onActivity`；没实现的跳过。`onKey` 收到读者的每一次按键，接手的功能自己调用 `preventDefault()`；功能退役后这个键交还宿主。
- 退役按 `id` 或句柄匹配：只匹配到句柄时只停止 `sync`、不拆安装（设置页的导航）。
- 功能内部的拆分就是普通的模块拆分，状态留在模块自己的闭包里，跨功能不伸手进别的模块的状态。

## 理由

- 开关、测试覆盖、让位、契约依赖都是「关于这个功能」的事实，放在功能自己的清单里，加一个功能只改一处，漏写由类型检查发现。

## 代价

- 清单的形状要稳定；汇总生成的内容不能手改。

## 重审条件

- 钩子继续增多（例如出现第二类键盘事件或第二种观察来源）时，按事件类别分组，或全部改为向观察总线声明订阅。
