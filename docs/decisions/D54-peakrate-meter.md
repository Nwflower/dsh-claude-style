# D54. 峰谷电表：作息表是数据源的快照，判定在浏览器按真实时刻做

- **状态**：已实施
- **分组**：功能
- **关联**：D11、D12、D29、D42、D51

## 决定

- 峰谷时间没有接口可用：供应商只发布作息表，没有任何一处按「此刻是不是峰时」作答。宿主半边取公开目录 `https://offpeakclock.com/pricing.json`（`schemaVersion` 为 1），校验成 `RateProfile` 后经 `/dsh-claude-style/peakrate` 下发；浏览器半边不直接访问第三方，也不知道数据源的地址。
- 读取顺序是磁盘缓存优先、包内快照兜底：缓存写在 `$DSH_HOME/cache/dsh-claude-style/peakrate.json`，不比包内快照旧时采用；快照来自 `packages/host/data/peakrate-catalog.json`，构建时复制成 `lib/peakrate-catalog.json`。新旧按文档自身的 `updatedAt` 比较，两边都没有时按文件修改时间，因此插件升级带来的新快照会盖过旧缓存。
- 调度：路由第一次被请求时载入目录并启动 24 小时定时器（`unref()`，不阻止进程退出），每次成功拉取后写回磁盘缓存。`GET` 答当前持有的目录，`POST` 先拉一次再答，浏览器半边读到的副本超过 24 小时时用它。定时器只在浏览器半边问过之后才存在，功能关掉后页面不再问，宿主也不再拉取。
- 判定全部在浏览器半边，只按真实时刻：墙钟在 profile 自己的 IANA 时区里读，墙钟时间先换算成真实时刻再与此刻比较，日内加法在时区自己的日历上做，所以夏令时切换与跨零点窗口都按真实时间算。优先级是限时活动、法定节假日整日谷价、星期过滤与峰时窗口；跨零点的窗口归它开始的那一天，开始那天是节假日还会压掉它的次日凌晨。
- 只有匹配到 profile 的行画徽章，匹配不到的模型什么都不显示。倍数与倒计时取自数据源自己的徽章文本，按外来字符串用 `textContent` 上屏（D11）。
- 宿主半边允许的 catch 增加两处，理由写在处所：数据源不可达或答的不是本版本能读的文档时记警告并沿用当前目录；磁盘缓存读不了或写不进时记警告，本轮结果照常（D12）。
- 校验时区用构造 `Intl.DateTimeFormat` 探一次：平台认不认这个时区，没有别的判断方式。profile 自己的时区探不通就丢掉整条 profile，节假日所属时区探不通就只丢掉这个字段、改用 profile 自己的时区读节假日。这是 D12 之外新增的第三处 catch，只在这里，浏览器半边因此不必再为时区兜底。

## 理由

- 「此刻是不是峰时」只有浏览器知道，作息表却是全量数据：宿主取一次、留一份在磁盘，胜过每个页面各取一次。
- 数据源是社区维护的快照而不是接口，供应商调价不会通知：判定规则必须留在本地代码里，取回来的只是作息。

## 代价

- 首次运行要能连上数据源，连不上就按包内快照判定，直到插件升级带来更新的快照。
- 数据源里的错误（零长度的作息窗口、写成时刻区间的活动）按没有这条 profile 丢弃，界面上表现为不显示徽章，只在覆盖审计里看得出来。

## 重审条件

- 供应商提供机器可读的时段接口时改接它；宿主的模型目录直接给出峰谷标记时改用宿主的。
