# D48. 文档流程

- **状态**：部分实施（决策一文件一条、AGENTS.md 只留工作流与红线已实施；索引生成、变更片段、README 生成、把可由工具强制的规则移进 lint 待实施）
- **关联**：D42
- **现状**：决策记录在 `docs/decisions/` 下一文件一条，索引 `docs/decisions/README.md` 手写；CHANGELOG 与中英文 README 手工同步；作用域前缀、`:has()` 位置、停止线与注释规范仍写在 AGENTS.md 里，等 D37 与 lint 接手

## 决定

- 决策一文件一条，文件名 `D<编号>-<英文短名>.md`，模板固定为：标题；状态（已实施 / 待实施 / 部分实施，待实施的写明现状）；关联；可选的迁移说明；决定、理由、代价、重审条件四节。编号稳定，代码注释按编号引用；被推翻的编号作废、不复用，新决策追加编号。事故经过与演变过程写在提交说明里，不进决策文件。
- 篇幅：四节都以要点列出，每条讲一件事；「理由」「代价」「重审条件」各不超过三条。「决定」里出现与标题无关的主题时，说明这条决策该拆成两条。
- 索引由脚本从各决策文件的标题与状态生成。
- 变更记录：每个改动在 `changes/` 下放一个结构化的小文件，中英文写在一起，带分组与「是否影响外部契约」的标记；发版时由脚本汇编成 CHANGELOG 的双语格式。
- README：功能介绍从功能清单（D42）的描述字段生成中英文段落；安装、截图与许可等部分手写。
- AGENTS.md 只留工作流与红线，决策里已有的规则只写编号；能由工具强制的规则写进 lint 之后，从 AGENTS.md 里删掉。

## 理由

- 一个长文件里的长段落，读的人要花很多力气才找到要的那一条；每条一个文件、固定模板，改动与引用都更准确。
- 中英文与 CHANGELOG 手工同步，容易漏、也容易和并行的会话冲突。

## 代价

- 生成的文件不能手改；脚本的格式要和现有 CHANGELOG 的格式完全一致。

## 重审条件

- 无。
