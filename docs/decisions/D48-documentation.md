# D48. 文档流程

- **状态**：已实施
- **分组**：分发与流程
- **关联**：D42
- **现状**：决策一文件一条，索引由 `scripts/decisions-index.mjs` 从各文件的标题、状态、分组与取代关系生成，持续集成核对它与文件一致；每个改动在 `docs/changes/` 下放一个结构化的小文件，`scripts/changelog.mjs` 把它汇编成 CHANGELOG 的 `[Unreleased]` 一节，发版时汇编成版本一节并清空该目录，持续集成核对这一节与文件一致；`scripts/lint.mjs` 管三条不需要构建的规则（停止线、Markdown 链接、决策编号引用）；功能一览由 `scripts/features.mjs` 从各功能清单的 `description` 字段汇编进 `docs/FEATURES.md` 与 `docs/FEATURES.en.md`，持续集成核对；README 与其余公开文档仍手写；停止线已在 lint 里，注释规范仍只在 AGENTS.md；作用域、`:has()` 位置与令牌门已由构建检查（D51）

## 决定

- 决策一文件一条，文件名 `D<编号>-<英文短名>.md`，模板固定为：标题；状态（已实施 / 待实施 / 部分实施）；分组（索引里的分组名）；关联（取代了哪些编号也写在这里）；可选的现状（待实施与部分实施写明）；决定、理由、代价、重审条件四节。编号稳定，代码注释按编号引用；被推翻的编号作废、不复用，新决策追加编号。事故经过与演变过程写在提交说明里，不进决策文件。
- 篇幅：四节都以要点列出，每条讲一件事；「理由」「代价」「重审条件」各不超过三条。「决定」里出现与标题无关的主题时，说明这条决策该拆成两条。
- 索引由脚本从各决策文件的标题、状态、分组与取代关系生成，持续集成核对它与文件一致；索引里的一行由文件自己给出，没有第二处手写。
- 变更记录：每个改动在 `docs/changes/` 下放一个 `<短名>.json`，中英文写在一起，带日期、分组、组内次序与「是否影响外部契约」的标记；`scripts/changelog.mjs` 把它汇编成 CHANGELOG 的 `[Unreleased]` 一节，发版时用 `--release` 汇编成版本一节并把文件清空。CHANGELOG 里这两类小节都不手改，持续集成核对小节与文件一致。
- README：只留预览、安装、字体、皮肤中心交接与许可等手写部分；功能一览与设置说明放在 `docs/FEATURES.md`、`docs/FEATURES.en.md`、`docs/SETTINGS.md` 与 `docs/SETTINGS.en.md`，README 用链接指向它们。功能一览从功能清单（D42）的描述字段生成中英文两条目，夹在标记之间由 `scripts/features.mjs` 汇编。
- AGENTS.md 只留工作流与红线，决策里已有的规则只写编号；能由工具强制的规则写进 lint（`scripts/lint.mjs`）之后，从 AGENTS.md 里删掉。lint 管的是不需要构建就能判定的几条：停止线、Markdown 里的相对链接、注释与文档引用的决策编号；已经由构建检查（D44、D51）或冒烟用例盯住的规则不再进 lint。

## 理由

- 一个长文件里的长段落，读的人要花很多力气才找到要的那一条；每条一个文件、固定模板，改动与引用都更准确。
- 中英文与 CHANGELOG 手工同步，容易漏、也容易和并行的会话冲突。

## 代价

- 生成的文件不能手改；脚本的格式要和现有 CHANGELOG 的格式完全一致。

## 重审条件

- 无。
