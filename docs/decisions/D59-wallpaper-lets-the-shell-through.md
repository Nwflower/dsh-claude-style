# D59. 壁纸插件在外壳下作画时，本插件不画那几处外壳

- **状态**：已实施
- **分组**：宿主边界
- **关联**：D3、D30、D49、D51

## 决定

- 壁纸插件（`dsh-plugin-wallpaper-engine`）在 `body` 上挂 `data-we-wallpaper`，壁纸本体画成 `position: fixed; z-index: -2` 的一层；这个标记在即「有壁纸正在显示」，插件装了而没在播壁纸时它不在。本插件读这一个属性来让位。它是别的插件的标记，不进 D3 的宿主契约表；读法与其他第三方的修边一样，落在用它的那几张表里。
- 标记在时，本插件不画外壳：`theme/tokens.css`、`theme/typography.css`、`theme/chrome.css` 里把不透明画布刷到 `<body>`、`#root`、侧栏、对话列与窗口外框上的规则加 `:not([data-we-wallpaper])`，Windows 标题栏那几条（把外框刷成画布、把两条列刷过标题栏条）同样加。加的是门口：那几条规则原来的配色门一个字不动（D30）。
- 标记在时，`--dsw-alias-bg-base` 与 `--dsw-specific-sidebar-fill` 在 `theme/third-party.css` 里清成透明，规则挂 Claude 配色门，DeepSeek 品牌另写一条同门的（生成的令牌块按深浅与品牌分档，特异性要同档才反超得了）：壁纸插件自己的清底不带 `!important`，样式表也在本插件之前，本插件按 Claude 一档重设这两个令牌会把它的清底反超。
- 侧栏元素自己那条 `--dsw-specific-sidebar-fill` 写在上面被让开的规则里；让开之后元素改用从 `body` 继承下来的清空值。
- 皮肤自己的面（弹层、账号弹层、搜索面板、卡片）照旧不透明，与配色是否 Claude 无关。
- 配色选「跟随宿主」时不画这些画布本来已经成立（D30），本决定补的是「配色留 Claude、只让外壳」这一档。

## 理由

- 外壳是插件自己的声明，让位就是这几条规则不生效：配色的门留着，换回 Claude 时一切照旧，也不用和谁比特异性。
- 让步按面分：外壳让给壁纸，读者在卡片与弹层里读到的还是皮肤的肤色与对比度。
- 读的是「有壁纸正在显示」这一个标记，而不是插件装没装：插件在而没播壁纸时，页面仍是皮肤的实色。

## 代价

- 壁纸在时，Claude 一档剩下的实色面只有卡片类；`--dsw-alias-bg-base` 被清成透明，宿主自己读这个令牌的表面也一起变透明，这与壁纸插件想要的结果一致。
- 别的插件换了标记名或换了图层做法时这几处要跟着改；这个外来的属性不在构建的属性检查之内（D51 只管 `data-dsh-*`），失配要靠冒烟的壁纸用例发现。

## 重审条件

- 宿主提供主题层级或令牌分层机制时，外壳的让位改由层来声明（与 D30 同一条件）。
- 壁纸插件提供公开的「让开外壳」契约（例如它自己带上 `!important`，或读宿主的层）时，删掉这几处门。
