# D34. 对话导航：皮肤画导航条，跳转按宿主自己的刻度

- **状态**：已实施
- **关联**：D16、D41、D44
- **迁移**：滚动位置的写入改经滚动唯一主人（D41，待实施）

## 决定

- 宿主自带轮次导航条（ui-chat 的 TurnNavigator）：每一轮一个刻度、间距 10px，跟随阅读位置，点刻度跳到那一轮（不在已加载窗口里的先翻页再定位），`turnOutline` 投影让它一进会话就覆盖全部轮次。皮肤在同一个插槽（导航条的父元素）里放自己的导航条，刻度间距与展开后的列表行高相同（24px）；宿主的导航条打上 `data-dsh-claude-turn-nav-replaced`，设为不可见但保留布局。位置照搬宿主给它导航条的规则（右侧 12px、竖直居中于对话顶部到输入区之间、最高为这一段减 64px、最多十轮），窄对话下隐藏用同一个容器查询，摆放不读布局。
- 指针碰到皮肤导航条立刻展开一张卡片（共用弹层外壳，D16），每一轮一行写开启这一轮的提问，每一行正好落在它的刻度上：卡片列表的盒子与导航条的盒子重合，列表滚动距离等于刻度轨道的滚动距离，行尾短横线的右端与刻度的右端在同一条竖线上。卡片只淡入淡出，不用外壳的上浮动画；打开没有停留时间，关闭沿用共用宽限。卡片挂在导航条所在的插槽里（对话栏 `centerCol` 之内），指针停在卡片上仍算停在对话栏上。
- 轮次列表照宿主的 `mergeTurnRailItems` 合并两个来源：聊天快照的已加载轮次（`navigation.items()`）与 `turnOutline` 投影；两边都有的一轮用已加载那边的提问，提问为空才用投影的；没有提问的一轮用宿主 `chat` 文案表里的「第 {turn} 轮」。不在已加载窗口里的轮次刻度画得更淡。
- 阅读位置与跳转交给宿主的导航条：当前刻度读宿主的 `aria-current` 刻度；跳转按下宿主对应位置的刻度按钮。宿主的刻度按钮只带列表位置（`data-index`）并且只渲染滚动位置附近的那些，所以只有宿主导航条的刻度数（由滚动内容高度 `数量 × 10 + 2` 读出）等于合并出的轮次数时才按，刻度没渲染时先把宿主导航条滚到那里；30 帧内仍没出现就抛错。
- 已加载的一轮由宿主在按下刻度的同一时刻一帧写到位：皮肤在这一帧绘制之前把位置放回原处，再经滚动主人（D41）以最高优先级滑到宿主写的位置，只滑最后 480px。别人在滑行途中改了位置时滑行立即让出；不在已加载窗口里的一轮由宿主加载完之后定位，不加滑行；减弱动效时也不滑。
- Alt+↑ / Alt+↓：焦点在有草稿的输入框、或有模态框与菜单占着前景时不接管；连按在 1.2 秒内从上一次去的那一轮接着走。页面上有 dsh-plugin-msg-nav（它的样式表在 `<head>` 里）时这两个键留给它。跳到的那一轮第一行出现时打上落点标记，画一条 1.4 秒淡出的强调色横线；减弱动效时横线静止显示同样的时间。
- 监听挂在皮肤自己的节点上，随节点去掉；滚动或窗口变化合成每帧一次去读宿主的当前刻度，刻度元素与位置都没变时不读布局。

## 理由

- 宿主的跳转（翻页、定位、阅读位置）完整可靠，按它的按钮就整套复用；展开的列表要和刻度重合，两边间距必须相同，而宿主的刻度由虚拟列表按固定 10px 摆放、改不了，所以导航条由皮肤自己画，宿主的那条留着只为被按。

## 代价

- 依赖宿主导航条的结构（插槽里唯一的 `nav`、它的 `_scroller`、`data-index` / `aria-current` 刻度、10px 间距与 6px 端距）、摆放规则与容器查询，以及 `navigation` 与 `turnOutline` 的形状；宿主改了这些，按键会在 30 帧后报错、位置会偏。
- 宿主的刻度按钮在宿主导航条不可见时失去键盘焦点，皮肤导航条不接受焦点，键盘读者用 Alt+↑ / Alt+↓。

## 重审条件

- 宿主开放「跳到某一轮」的接口或刻度上带轮次号时改用接口；宿主导航条的间距可配置时改回重绘宿主的导航条。
