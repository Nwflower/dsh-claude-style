# D5. 模型文案是数据，不进产物

- **状态**：已实施

## 决定

- `src/model-descriptions.json` 构建时按 `src/model-descriptions.schema.json` 校验后复制到 `lib/`，浏览器第一次绘制模型选择器时经宿主路由读取。
- 查找顺序：精确条目 → 家族规则 → 档位规则 → 目录自带文本。
- 文案属于产品线，不属于某个版本：同一产品线按名字模式映射到同一句，版本迭代与退场都不改。
- 不写自造的档位前缀（「旗舰档：」），不重复行里已有的模型名。
- 家族规则有顺序且必须限定范围（`flash` 规则只作用于 deepseek）；「最强」「旗舰」这类最高级只出现在绑定具体版本号的精确条目里。
- 同一文档的 `brands` 把模型绑定到厂商组合标；没有规则认领的模型不画组合标。
- 扩充文案表不需要改 JS。

## 理由

- 模型目录变化快，更新文案不应要求改代码发版；写给某个版本的描述最终会挂到别的版本上。

## 代价

- 第一次绘制选择器多一次异步读取；文案规则有学习成本。

## 重审条件

- 宿主的模型目录接口直接提供本地化文案时改用宿主的。
