# D60. 设置读写走官方 Config 表单，非 loopback 页面只读设置文档

- **状态**：已实施
- **分组**：宿主边界
- **关联**：取代 D10；D11、D12、D29、D46

## 决定

- 浏览器半边写设置只有 `configForms` 一条传输：绑定宿主实际提供的命名空间（候选依次为加载器入口 id、包名、`cordis.patch.yml` 插入的 id，以宿主的命名空间目录为准），读写都经表单控制器（值、写队列、修订号栅栏）。命名空间晚到时订阅目录，到达即绑定。
- 宿主对非 loopback 页面（局域网地址、隧道域名，由浏览器侧的 `location.hostname` 判定）只给内存态的表单：命名空间目录恒为 `unavailable`，从不读取设置文档，写入一律不落盘。皮肤以目录的 `unavailable` 认出这种页面，改用表单服务自己所依赖的读取 `remote.settings.describe()` 取自己命名空间的合并值，在 `settings/document-updated` 事件与 `connection/reset` 之后重读；宿主拒绝这次读取时抛出。
- 这种页面上皮肤的设置页只读：开头一行说明改动要在运行 DSH 的电脑上做，所有行放进一个禁用的 `fieldset`，标签页仍可切换浏览。皮肤不经 `remote.settings.mutate` 绕过宿主替远程页面保存设置的限制。
- 宿主半边导出 `Config` 作为 schema，只有 `.volatile()` 字段进表单。schemastery 以顶层 await 加守卫导入，解析不到时 `Config` 为 `undefined`、皮肤照常加载——这是「导入不包 try/catch」规定的唯一例外。
- 设置席位注册为 `plugins.bundle.config`（键为包名）；宿主没有 `configForms` 时才注册整页的 `settings.section`。
- 偏好字段只有一份声明：`packages/contracts/src/prefs.ts` 的 `PREFS_DEFAULT`。宿主半边 `packages/host/src/settings.ts` 用它生成 `Config`（宿主构建把 contracts 的值内联进产物，contracts 不进 npm 包）；浏览器半边的默认值与取值集合给出表单答复之前的初值与读到值时的规整。
- 字段类型按默认值的类型取纯 `string` / `boolean` / 字符串数组：取值集合在消费处判定，浏览器半边读到什么都做规整。存下的值可能还是早先类型的偏好，字段同时接受 `boolean` 与 `string`：`autoPopover` 早先是开关、后来长成多档，`chatAnimations` 早先是多档、后来又回到开关。宿主在启动插件之前用 `Config` 校验配置行，类型不符即校验失败，整个包都不启动——私有路由、设置表单与浏览器半边一起缺席；浏览器半边把两种类型都读成对应的取值。偏好的默认值换类型时，这个键同一次改动里加进这份名单，冒烟的宿主半边用早先类型的值校验一遍 `Config`。
- 偏好只存在宿主的设置文档里：早先存进浏览器本地存储的昵称与封号页语言，在表单第一次带值时写进表单，表单持有自己的值后删掉本地那份；只读页面不做这一步。

## 理由

- 官方表单自带写队列与修订号，皮肤不重复实现一套同步。
- 皮肤的外观由偏好决定：远程页面拿不到设置文档时整套外观回到出厂默认，与宿主上的设定不符；读取本身宿主照常应答，只读不越过宿主不替远程页面保存设置的边界。

## 代价

- `Config` 的顶层 await 让宿主半边晚一步求值（加载器本就等待导入，无实际影响）。
- 远程页面上的设置只能看不能改。

## 重审条件

- 宿主提供不依赖 `Config` 的设置注册方式，或 `configForms` 契约再变。
- 宿主的表单服务对已认证的远程页面也读写设置文档：那时目录不再是 `unavailable`，皮肤回到表单这一条路，这条决策的只读部分随之删去。
