# D103. 流式增长的低估单独成层，基准计价保持准确

细则不取代 D104 的分项计价来源，只把「系统性低估」从基准系数里拆出来，交还给流式增长动画。

## 背景

字符类别计价系数先前整体偏低。这份偏低有一个用途：流式输出的实时读数宁可低估再增长，也不先高估再回退——结算到达时数字向上跳一下是自然的，向下回退则刺眼。低估因此被烘进基准系数，详情栏的分项也一并继承了这份偏差，中文与推理内容被摊薄。两件事共用一份系数，调准一处就动了另一处。

## 决定

- 基准 `textTokens` 的字符类别系数对 DeepSeek 分词器（V3/V4 同一族）拟合：语料覆盖中文正文、学术、代码、日志、外文、小语种文字、emoji 与中英混合，按同一 `classOf` 切段提取特征，对分词器计数做约束最小二乘。词长表 `WORD` 与 `DIGIT_GROUP` 守在精确锚点上（三位数字恰好一个 token），只放开语料能良好识别的字符类别费率。详情栏分项直接用这份基准。
- 流式读数另套一层低估系数 `STREAM_UNDERESTIMATE`（estimate-scale.ts）：写出的数 = 基准估算 × 路由学习乘数 × `STREAM_UNDERESTIMATE`。这份低估只服务增长动画，使 live 读数在结算前持续低于结算值，增长单调向上。
- 结算学习读的是**未乘低估系数**的基准估算与结算差，学习乘数仍落在 `SCALE_MIN..SCALE_MAX`；低估系数不参与校准，不会反馈进学习。
- 低估系数与基准准确度各自独立可调：调基准不动画手感，调动画不动分项准确度。

## 后果

- 详情栏分项不再继承流式的刻意低估，按基准系数计价；流式增长动画保留低估再增长的手感。
- 全局字符费率拟合在留出会话集上泛化良好（加权绝对误差约 5.7% 降到 3.4%，p90 约 9% 降到 5.5%），予以保留。按语境另套乘数的做法经留出验证被否决：乘数随会话内容构成漂移，在标定集上拟合后到留出集反而更差（过拟合）。推理正文按基准费率计价本就准确（先前请求级回归把差额归给推理是共线伪影）；残差按内容分布起伏，是静态字符类别模型的固有底线。`PUNCT` 类把 ASCII 标点与非拉丁文字混在一起，小语种与外文残差由此而来，细化字符类别可进一步收敛，但会增加模型复杂度，须同样过留出验证。
- 拟合语料与脚本留在 `.debug/tokenfit/`（一次性产物，不进包）；本地会话日志只作验证集，不作训练集。

## 重审条件

- 宿主提供按类别归因的上下文投影时（D104），基准估算删除，分项改读投影；流式低估层仍为增长动画保留。
- 提供方分词器更换、基准系数明显偏离时，重跑约束拟合并更新常数，低估层不动。
