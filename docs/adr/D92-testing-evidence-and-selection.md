# D92. 测试按证据分层，运行范围由一种选择器表达

- **取代**：D87

## 背景

测试要回答的问题分属不同层次，代价差别很大：逻辑层在秒级给出答案，页面层要起浏览器、等页面稳定。把检查堆在一条通道里，改一个文件也要付出整条通道的等待；断言写成钟点与像素量值时，同一份代码在忙碌的机器上失败。

替身宿主上的装载检查与读者行为规范曾经各有入口，端到端探针又另立通道。它们读同一份构建产物、装同一套替身页面，却让调用者记住多种参数组合。覆盖事实也分散在功能清单、规范头部与持续集成的路径判断里，新增一个功能需要同步多处。

规范还需要稳定的触点：经私有路径导入源码、拼写皮肤标记、复制样式表做夹具，都会让纯结构改动使测试变红。浏览器通道只在推送之后观察而不给推送结论时，主干回归也无法归因到引入它的那次推送。

## 决定

- 测试只有一个完整运行入口 `npm run verify`。默认请求判定工作区改动到达的范围；`--full` 判定全部发布检查；`--only <选择器>` 点名范围。选择器是 `quick`、`browser`、`e2e`、`case:<名称>`、`feature:<目录>`、`scenario:<名称>`，可以逗号分隔或重复给出。`--force` 只控制是否重读判定缓存。
- 测试按证据来源分三层：逻辑层回答函数、引擎机制与其顺序；替身页面层在同一份构建产物与替身宿主上回答产物能否装载、功能安装与拆除是否成对、开关能否翻转、延后块能否到达，以及读者能看见的结果；真实宿主层在最新发布宿主上回答端到端行为。替身页面层只有一个正式运行器，装载用例与读者行为规范是用例种类，不再各立一条车道。宿主半边在 Node 中的核对属于替身页面层，不需要打开页面。
- 规范只经三条通道接触产品：声明的逻辑面与各包公开模块；宿主契约表与皮肤表面表；读者能观察到的结果。规范不导入源码私有路径，不拼写宿主或皮肤标记，不用替身换掉产品自己的代码，不留代码快照。
- 替身只站在系统边界上：宿主页面与服务、设置表单、模型服务、账户平台、操作系统焦点。观察浏览器自己的方法只为一项决策写明的代价，并在旁边写出是哪一项。
- 规范按「层/能力」组织，文件开头写明守护的能力、覆盖的功能目录与失败时读者哪里受损；编号是「层/能力/名称」。真实宿主场景由功能清单的 `scenarios` 声明归属，冒烟用例由 `cases` 声明；共享覆盖表合并这些清单事实与规范的 `@features`，持续集成、按功能选择和覆盖报告都读它。
- 断言要证明自己是活的：规范要被已知故障打红过才算数。故障是对源码的补丁，在临时副本里构建并运行；故障语料取自历史修复中仍能在当前树上逆转的那些，以及按规范意图写下的故障。因已被认领的产品缺陷而失败的行为测试由人写进隔离记录：照常运行与打印，失败不阻断，通过反而阻断，直到条目移除。隔离记录只减不增，不设重试转绿或自动隔离。
- 断言读用户可观察的结果与页面自己记下的序列：属性、文字、元素在不在、盒子的位置关系、计算样式、正在运行的动画、滚动终点，以及帧回调序列满足的不变式。钟点阈值、帧数与单个像素量值不进断言。产品规格写明的时长与性能场景的耗时比值是例外；等待状态的限时只用来让卡住的等待按名字失败。
- 动效只在页面记下的序列上判定：序列单调、中间经过多个不同值、终点等于目标，曲线形状留在逻辑层。需要数帧的地方改读这些帧覆盖的时间跨度，阈值写成毫秒。行为测试按样式表声明的断点分视口档位，新断点先成为新档位。
- 外观用计算值快照对照：快照在真实宿主上读取，只收与字体无关的属性。仓库自己的行为与契约阻断合并；宿主输出的精确记录作为观察，与记录不同时报告而不阻断。观察记录按生成者与判定依据区分：判定依据随改动提交，可从源码重算的观察记录按需生成。
- 开发期不设本机测试闸门：改动以构建与真实页面为准，提交与推送不等待本机测试，构建也不等待测试锁。推送到主干时，云端给出这次推送的检查、构建、逻辑层和改动到达的替身页面范围；功能目录之外的改动跑完整替身页面。独立观察通道在只跑了部分目录的推送之后补跑完整替身页面，不进分支规则，已经跑过时不重复。拉取请求与合并队列的门禁不变。
- 发布前在主干完整运行一次全部检查，包括全量替身页面、三平台行为规范与真实宿主层，失败逐条修复、逐条重跑，全部通过后才切版本。版本标签触发的发布流程读同一提交的这次结论，为绿时只打包、跑不读页面的检查并发布；没有结论、结论不为绿或某条通道被跳过时，在打包前失败。
- 最新发布宿主上的真实宿主层与 macOS 行为规范每天各跑一次，不进分支规则，也不替发布矩阵作答。端到端只对宿主最新发布版本给出结论；本机宿主不同时，该层回答「未判定」。每道闸门带云端同一步骤的时限，超时时连同浏览器一起结束并释放锁。一次运行只对它读过的那棵树成立；行为层失败默认是产品缺陷，放宽断言的改动要在提交说明里写出旧断言误判了哪一种产品行为。

## 后果

- 调用者只需区分默认、完整与点名三种请求；按功能点名会同时选中清单登记的真实宿主场景。功能清单与规范头部是覆盖事实的来源，持续集成不再另猜一份目录映射。
- 替身页面层的两种用例共享正式入口与调度，单页打开、表达式求值、截图与关闭仍是开发调试命令，不构成另一条测试车道。
- 移动或拆分模块只改声明的逻辑面；改皮肤类名只改表面表；宿主改名只改契约表。规范身份不随源码移动改变。
- 替身页面的边界就是替身宿主的边界：替身渲染不了的界面只能在逻辑层对着随产品发布的样式表测，或交给真实宿主层。逻辑层跑在浏览器里，换成纯 Node 环境要先拆导入时的文档依赖。
- 推送带来的浏览器缺陷由这次推送自己的结论报出。红色的推送结论不阻止提交进入主干，由推送者修复；改动范围之外的影响由观察通道补报。发布前的完整矩阵仍是发布前提。
- 代价是清单需要登记场景归属；跨功能的公共场景可以留在公共层，此时按功能点名不会假装覆盖它。

## 重审条件

- 宿主提供官方插件测试环境时改用宿主的。
- 变异测试工具能直接驱动浏览器模式的逻辑层时，故障由它生成，语料只留历史缺陷。
