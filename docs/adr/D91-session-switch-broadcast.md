# D91. 会话切换是一件广播出来的事

## 背景

滚动主人、等待行、进程摘要、日期视图、统计面板绑定各自维护一套随会话失效的状态，各自也各自判断「会话换了没有」：容器还在文档里就当还是同一个会话，容器走了才清理。这套判断每一处都要写对，漏一处就留下上一份转写的节点——本轮排查的内存留存大多是这个形状。

宿主本来就在对话栏上写着当前会话的 id（`[data-phase="active"] [data-conversation-session]`）。谁需要知道切没切，读这一个标记即可，不必再从容器是否存活去推断。这份广播补在观察总线（D40）之上，不新增观察者：页面上的变化仍然只有一个总线在看。

## 决定

- 引擎提供 `conversationSession()` 与 `observeSession(callback)`：前者读当前会话的 id（会话未选时为 null），后者在 id 变化时同步回调一次，返回退订函数。它订阅对话栏的 id 属性、相位属性与子树变化，id 没变就不回调。
- 按会话建立的状态（缓存、观察、DOM 引用、清理函数）向这次广播登记，切换时整批释放；功能不再用「容器是否还在文档里」判断会话换没换。
- 广播只报告变化，不替功能决定放掉哪些对象：每个功能在自己的登记表里写明要释放什么。
- 广播不改变宿主的会话服务，也不等新会话挂载完成；它在页面看到新 id 的那个批次里发出。
- 一份状态属于按代、按界面还是按行时，不走这条广播；只有按会话的状态登记在这里（`ARCHITECTURE.md` 的持有期限一节）。

## 后果

- 漏写清理点在结构上更难发生：功能写登记表，不写探测；会话切换时释放的顺序按订阅先后，与 D40 的回调次序一致。
- 会话未选（hero 页）或 id 标记缺失时，广播给出 null，功能据此释放全部按会话的状态。
- 旧容器仍留在文档里时也不再冒充同一个会话：id 变了就释放。
- 一次切换里每个功能在同一个批次内完成释放，挂载新内容的批次再重新登记。

## 重审条件

- 宿主改为用服务或事件报告当前会话，而不在 DOM 上写 id 时，accessor 改读宿主服务。
- 出现需要区分「同一会话内的重新挂载」与「换会话」的功能时，广播要再报一个重新挂载的信号。
- 更多状态改为按会话释放之后，如果登记表本身成了新的复杂度来源，就把它收进引擎的作用域对象，由作用域统一建立与释放。
