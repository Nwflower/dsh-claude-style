# D115. 输入框在原位显示渲染结果，宿主编辑器的节点一个不写

## 背景

输入框是宿主私有的 Lexical 纯文本编辑器：节点类型在创建编辑器时就固定下来，插件无法再注册；根元素里的节点由 Lexical 调和，写进去的节点会被它当作外来改动撤销，Lexical 记下的选区、撤销历史与发送出去的文本也都以它自己的节点为准。草稿的 Markdown 与公式要在原位显示成渲染后的样子，宿主又没有为此开放扩展点（D43）。

## 决定

- 渲染结果画在覆盖层里：覆盖层是输入框的同级元素，挂在宿主的生长层（`input-grow`）末尾，随草稿一起在宿主的滚动容器里滚动；它不接收指针，读屏也跳过它。
- 宿主编辑器根元素里的节点一个不写：源码的隐藏与让位由一张按卡片生成的样式表完成，规则按结构位置（段落与段内子元素的序号）选中 Lexical 的行；渲染块借 CSS 锚点定位跟随它那一块源码的首行。草稿文本、选区、撤销与发送全部仍走宿主的路径。
- 切换按块：Markdown 顶层块是单位；选区碰到的块显示源码，其余块显示渲染结果；输入框失去焦点时整份草稿都显示渲染结果；输入法组合期间不重新切换。点进渲染块，点击落在下方透明的源码上，光标进入后该块展开。
- 含宿主部件（引用胶囊、命令胶囊、引用块、文本引用）的块始终显示源码：那些部件由宿主画，它们在源码里的文字不是 Markdown。
- 公式用 KaTeX 渲染，字体与样式取宿主页面已经加载的那一份，插件只带 KaTeX 的脚本，版本跟宿主样式表一致；块级与行内按宿主消息的规则判定，草稿里的样子与发出后消息里的样子一致。
- 草稿 HTML 先经清理再进页面，清理规则不为公式放宽：公式先输出为占位，清理之后由 KaTeX 在占位里自己构建节点。
- 原位渲染是输入框的默认行为，不设开关。

## 后果

- 正确性依赖 Lexical 纯文本模式的 DOM 形状（段落里每行一个文本 span，行与行之间是 `<br>`）与宿主页面全局加载的 KaTeX 样式表，两条都写进契约；宿主换编辑器结构或换掉 KaTeX 时，渲染块会对不上源码，要跑契约与规格才知道。
- 点击渲染块只能把光标放进那一块，落不到具体字符上。
- 渲染块里的链接与复选框不可点击：覆盖层不接收指针，点击属于编辑。
- 放弃的方案：在输入框下方另画一份预览（同样的内容显示两份）。
- 放弃的方案：向宿主编辑器注册装饰节点（插件无法注册节点，改动也会进入宿主的撤销历史与发送文本）。
- 放弃的方案：让插件自带 KaTeX 的字体与样式（与宿主那份重复，体积翻倍）。

## 重审条件

- 宿主为输入框开放装饰或渲染扩展点时，改为接入宿主的。
- 宿主输入框改用富文本模式或换掉 Lexical 时，重新确定源码与渲染块的对应方式。
- 宿主页面不再全局加载 KaTeX 样式表时，重新决定字体与样式的来源。
