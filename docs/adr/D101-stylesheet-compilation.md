# D101. 样式表编译成浏览器能分桶的选择器

## 背景

浏览器给每个元素找规则时，先按选择器最后一段里的类名、id、属性名或标签把规则分进桶里，只拿元素自己带的键去取桶。最后一段没有键的规则进通配桶，页面上每个元素都要拿它去试。皮肤的样式表里有两类写法落在这条路径之外。

一类是最后一段只有通配符、单独的伪类或多参数 `:is()` 的选择器。它们数量不到一成，却占了皮肤给一次样式计算增加的开销的大半，而且与页面上有多少元素属于皮肤无关：宿主每挂上一棵子树，子树里的每个元素都要逐条试一遍。

另一类是部件名。宿主的类名带哈希，皮肤在每棵挂上来的子树里逐个元素读类名，把自己起的部件名写成元素上的一个属性，样式表原先按这个属性匹配。全部部件规则因此共用同一个属性名的桶，带标记的元素要把它们逐条试完；标记要等变化观察的回调才写上，宿主在插入节点的同一个任务里读布局时，这批节点先按没有标记的样子算一遍样式，写上标记之后再算一遍。

## 决定

- 进产物的每条选择器，最后一段都带有浏览器能分桶的键：类名、id、属性或标签。构建拒绝最后一段没有键的选择器。
- 最后一段只靠多参数 `:is()` 或 `:where()` 取得键的选择器，由构建按参数展开成并列的几条。展开前后对同一棵树命中同一组元素，分量相同：分量较低的一支由永远成立的否定条件补齐，构建逐条核对分量。
- 一条规则确实要落在某个盒子的全部子元素上、或落在任意元素的伪元素上时，逐条登记并写明缘由；登记只许变短，构建拒绝不再对应任何选择器的登记项。
- 部件名是书写用的词汇。样式表与契约模块照旧用部件名书写；读部件名的选择器在产物里留空，由页面按宿主的类名写完，最后一段每个类名一条。元素一插入就带着宿主写下的类名，宿主在同一个任务里读布局时读到的已经是皮肤的样式。
- 类名来自标记遍历在页面元素上读到的：遍历每遇到一个部件表认得的带哈希类名就报上来，样式表只用页面上出现过的类名写完，遇到新类名时在读到它的那个任务里重写一次。
- 部件表里的区域、区域里跳过的子树与只在区域根下读的名字，写成不计分量的条件；写完的选择器与原先按属性匹配的写法对同一棵树命中同一组元素，分量相同。
- 遍历照旧把部件名写在元素上，供脚本自己的查询与结构关系读取；进产物的规则不读这个属性，写标记因此不再引起样式重算。功能自己指认的元素用另一个属性写部件名，写完的选择器在类名之外读它。
- 一个元素因为子树里有什么而得名的结构关系仍按 D9 由脚本写在持有它的元素上：这类标记只落在少数几个元素上，它依赖的判断浏览器无法从类名读出。

## 后果

- 页面上的选择器与源文件里写的不再逐字相同：展开后一条变成几条，部件名换成了类名。在开发者工具里按声明或按源文件里的其余片段回去找。
- 一个类名第一次出现在页面上时，带着它的那批节点要等遍历读到之后才有皮肤的样式：样式表在那个任务里重写一次，整页样式随之重算一次。此后带同一个类名的节点一插入就有样式。
- 遍历仍然要走：它是类名的来源，也仍然写脚本要读的标记，它的时间照旧随子树的大小增长。
- 测试里手搭的宿主结构要给元素写上部件表认得的类名；只写部件属性、不带类名的元素，样式表够不到。
- 放弃的方案：从页面上的样式表里读出全部带哈希的类名。常见的本地名（`root`、`title`、`row`）在宿主与各插件的模块里各有一个哈希，按样式表里声明的全部类名写完，样式表的大小与匹配祖先的开销都随装了多少模块增长，而一个页面上出现的只是其中少数。
- 放弃的方案：把部件名写成元素上的皮肤类名。分桶问题解决了，写入的时机不变，还要改写宿主元素的 `class`。
- 放弃的方案：在构建时写入宿主的哈希类名。哈希随宿主版本与各插件变化，构建时无从知道。
- 放弃的方案：用类名子串匹配本地名。子串匹配的规则仍然共用 `class` 这一个属性名的桶，并且会命中只是含有同一片段的邻居（D3）。

## 重审条件

- 宿主为这些区域提供稳定的属性契约时，样式表直接读宿主的属性，对应的部件名与它的解析随之删除（D3）。
- 浏览器对最后一段的多参数 `:is()` 按各参数分桶时，展开这一步删除。
- 脚本对部件的查询都改经类名之后，遍历只读类名，不再往元素上写部件名。
