# D111. fork 版本链承载消息回退，dsh-rewind 在场时交出写操作

- **取代**：D105

## 背景

消息撤回、编辑、重跑和删除需要回到同一个历史位置。DSH 公开给页面的写接口只有 fork：它复制指定事件前缀并创建配置完整的 Agent，原 Session 不变。单独修改页面会让读者误以为原 Session 被截断；单独 fork 又会在侧边栏不断产生看似无关的新对话，文件改动也不会随之恢复。

dsh-rewind 是另一个专做回退的插件：它在原会话里追加一条替换标记来就地回退，在文件改动前按文件保存原文。两个插件同时运行时，同一条消息下出现两套回退入口；每次工具执行前两边各存一份检查点；同一个会话里还会混进两种回退方式：本插件 fork 时把对方的替换标记复制进新会话，计算轮次时又把对方已撤回的消息算在内。它的作者提议由它承担回退引擎与存储，本插件只保留界面，代价是版本历史要按就地回退重新设计。

## 决定

- 不修改 DSH。四个消息操作都经过插件的同一条「计划、确认、fork、提交」路径，不保留任何直接 fork 的旁路。浏览器只调用宿主的 sessions.fork() 创建 Agent，底层 SessionStore 和子代理 fork 都不代替它。
- 插件用最初的物理 Session id 作为稳定的逻辑对话 id，另记活动 Session id 与完整版本链。普通侧边栏只显示活动版本；非活动版本写入宿主归档并保留在版本历史中，不删除原会话事件。打开归档版本时先取消归档，原置顶状态随活动版本转移。
- 宿主半边在每轮工具执行前保存插件自有的 Git 树快照，在文件工具第一次修改路径前保存原始字节、符号链接与权限。快照、fork 血缘和版本元数据持久化到插件自己的 DSH Home 目录。
- 回退确认绑定源会话头、目标轮次和确认时的工作区树。提交前任何一项变化都拒绝执行；恢复失败时源版本保持活动，已创建的 fork 记为失败版本。代码恢复失败也要先尝试恢复确认时的安全快照。
- 文件恢复只覆盖检查点记录的工作区内容。Git 提交、外部服务、进程及其他命令副作用不宣称可以撤销。缺少完整检查点时只允许读者明确选择消息回退，界面不得暗示代码也已恢复。
- 逻辑会话隐藏宿主 fork 的继承分隔行与 `forked` 收尾行，保留正常轮次；普通 fork 的分隔行不受影响。功能开关卸载时移除版本隐藏属性、页面观察器和弹窗。后续更新消息操作、fork 边界、检查点格式或版本展示时，必须同时维护血缘继承与清理路径，并运行真实 Git 宿主核对和消息操作真实页面场景。
- 宿主未提供的能力继续由插件私有路由组合，路由沿用 D75 的鉴权与输入边界，不增加绕过宿主 Agent 创建的第二条路径。
- dsh-rewind 在场时，回退的写操作整体交给它：四个动作的按钮、编辑框与确认对话框都不出现，已经打开的随即关闭，进行中的确认按取消处理；宿主半边在每一轮开始时不再为任何会话记录检查点。已有逻辑对话的版本隐藏与「查看版本历史」照常保留，它们只读插件自己的元数据，不写会话。
- 在场判定按 D74 的方式进行，两个半边各自判定，不跨变化缓存。浏览器半边读启动图里它的条目与它挂在页面上的样式表，跟随样式表的挂上与撤下；宿主半边在每一轮开始时读加载器里它那一条的纤程是否处于活动状态，页面没有打开时记录同样停下。
- 设置页的「消息操作行」保持可用，开关仍然管着版本历史那一部分；它在场期间，这一行下面写明撤回、编辑、重跑与删除由它提供。
- 不设置它的接管标记 `data-dsh-rewind-claim`：两边会同时退下，页面上就没有回退入口了。不为它的按钮补上本主题的外观：它的类名不是它承诺过的接口。

## 后果

- 读者看到的是一条逻辑对话和原位置继续的历史；物理 Session id 仍会变化，其他插件或原生「复制 Session ID」看到的是活动物理版本。
- 插件承担快照存储与版本维护成本。更新宿主事件形状、文件工具意图、fork 标题行为或侧边栏行契约时，这些代码是明确的重审点。
- 检查点让宿主重启后的已记录轮次仍可恢复；插件安装前、记录不完整或 dsh-rewind 在场期间的轮次只能回退消息。
- dsh-rewind 在场期间，回退入口是它自己的外观；新的回退不进入版本链，版本历史只列出它到来之前的版本。
- 判定依赖它的包名、它给样式表打的标记和加载器条目的形状，三者都不是它承诺的接口。它改名或换挂载方式后，本插件会重新记录检查点、重新提供写操作，两套回退再次同时出现，要对照它的新版本核对。
- 放弃的方案：改写原 Session 的持久化日志以保留同一个 Session id；只隐藏页面消息，不恢复模型上下文和文件；用 subagent-fork-in-process 代替普通会话 fork。把回退引擎与存储交给 dsh-rewind、本插件只保留界面：就地回退不产生分叉，版本链与逻辑对话都要重做，本插件的回退还要跟随另一个包的发布节奏，减少的维护量抵不上这份重写。两个插件同时在场时都保留写操作：背景里列出的冲突全部留在页面上。

## 重审条件

- DSH 提供原 Session 内回退、完整工作区恢复或逻辑分支展示接口时，以新的 ADR 取代本条并迁移到宿主能力，删除插件重复实现。
- dsh-rewind 公开在场判定或版本展示接口时，判定改用它的接口，删除对它包名、样式表标记与加载器条目的依赖。
