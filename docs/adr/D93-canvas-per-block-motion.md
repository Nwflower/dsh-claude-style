# D93. 逐格独立相位的动效由一块画布绘制，令牌仍是唯一的取值来源

## 背景

推理等级滑块的顶档场地由 5 行方块铺成，每块两条动画加两个伪元素各一条：宽度 1440 的轨道上约 940 个动画实例。进入顶档那一帧要把这些动画一起启动，松手时把摘除拖动标记后待处理的样式一次算完，停驻时每块的关键帧每帧在主线程重绘（#300）。观感要求每块有自己的闪烁相位，CSS 里一个相位就是一条动画：把 235 块并进十几条动画，同组方块会同步闪，宽轨道上会显出竖带。于是这片场地的成本与方块数成正比，样式表里没有把比例调下来的写法。

## 决定

- 逐格独立相位的场地由一块 canvas 绘制。网格在设备像素里求解，每块的相位、周期、峰值、入场时刻、流光偏移与强度在建立时算好，每帧在写阶段按包络画一次（`features/effort/matrix-field.ts` 存算，`features/effort/matrix.ts` 存画）。
- 画布仍从令牌取值：时长与曲线经 `motionMs`、`motionEaseAt` 读出，颜色经 `engine/colour.ts` 把 `--dsh-claude-apex*` 画回 sRGB。令牌缺失或值画不出来时抛出，不设回退色（D12、D9）。
- 关键帧的停顿与曲线写在功能自己的纯模块里，可以用逻辑规格逐段核对；样式表只留容器的显隐、圆角与溢出。
- 帧只在同时满足「顶档点亮、卡片打开、页面可见、未要求减少动效」时申请，减少动效只画一帧静态底色，卡片关闭或页面隐藏后自行停帧。画布与监听在拆除时成对收走。
- 行为层判断这类场地在不在动，改读画布自身的像素：`getAnimations()` 看不见画布。替身页的安定判据数调度器的趟数，不数页面上的每一帧，一块自己申请帧的场地不会被当成页面还在反应（D92）。

## 后果

- 顶档场地在页面上的动画实例从约 940 个降到 0 个；同一台机器、同一手势下，拖到顶档与停驻的帧间隔不再有慢帧，松手的长帧随之消失。
- 形状与节奏住进代码：方块尺寸、缝、圆角、左端渐隐与四段包络的百分比，改观感要改代码并重新构建；样式表里改一条属性即时看效果的循环没有了。
- 画布内部不在样式检查、外观快照与重要性走查的覆盖里，正确性靠截图与纯函数规格。
- 主线程每帧要算一次颜色并画一次方块；页面被别的工作占满时场地会跟着停，不同于合成层上的动画。
- 令牌链坏掉时表现为颜色错误，只能靠取色失败抛出暴露；令牌改名不经过抛出的路径会静默沿用旧值。
- 放弃的方案：把 940 条动画减到十几条（同组方块同步闪，宽轨道显出竖带）；每帧往卡片上写自定义属性和全字重算相位（每个方块每帧重新解析样式）；静态图加两三条合成层动画（逐格闪烁与散粒流光都留不住）。

## 重审条件

- 浏览器提供逐元素、不经过样式重算的相位驱动手段（可动画的遮罩、每元素独立的时间轴）时，这片场地改回样式表。
- 顶档观感换成不需要逐格相位的整片扫光时，同样改回样式表。
- 宿主公开自己的动效令牌并允许脚本读取时，画布的取值改为读宿主那一套。
