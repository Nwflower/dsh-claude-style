# D90. 已看过的消息按上次高度跳过离屏排版

## 背景

宿主切换会话时卸载整份转写、再挂载另一份，每一行都是新节点。皮肤已经用 `content-visibility` 跳过离屏行，但只有在行完成过一次真实排版之后才敢跳过（row-skip）。于是切换一个长会话时，每一行仍要先真实排版一遍，样式重算占据切换任务的大部分时间；真实宿主上两个百行会话之间的一次切换，任务时间约一秒半，其中样式重算约一秒。

行的高度由内容、对话栏宽度与界面字号决定。宿主给每个聊天行写了节点键，行种类与分组部位区分同一条消息的推理行与回答行；这些键在同一条消息的每次挂载之间不变。上一次挂载得到的真实高度因此可以供下一次挂载使用，只要列宽与界面字号没有变化。

## 决定

- `row-skip` 记录每一行成功排版后的真实高度，键是节点键、行种类与分组部位；缓存按最近使用保留最多 4096 条，超出时最旧的离开。
- 在一次挂载批次的绘制前阶段，缓存里有高度的行直接带上 `contain-intrinsic-size` 与标记，样式表从这一帧起就可以跳过它；缓存里没有的行仍等第一次真实排版之后才标记。这样切换回看过的会话不必先把每一行排版一遍。
- 高度只在取它时的布局下有效：对话栏宽度变化或界面字号变化时清空缓存、摘掉标记，按新布局重新排版后再记录。宽度连续变化时（侧栏开合、拖拽分栏、窗口缩放），等宽度停止变化后再清空与重排：变化中的宽度不是行要排版的那一个，每帧重排一次会让长会话按帧数重复支付整份转写的排版。
- 仍在流式输出的行不记录高度：它下一次挂载时已经不是取高度时的内容。用户行、隐藏段落与折叠内容里的行保持不跳过，它们的测量或隐藏盒子依赖真实排版。
- 观察总线在一个批次移除子树时，把该子树里的匹配从各选择器的清单中清除，不等下一次读取：没有读取者的选择器否则会一直留着切换走的会话的整份转写。清除发生在同一批次的追加之前，页面内移动的节点仍然留下。

## 后果

- 切换回看过的长会话，样式重算与任务时间明显下降，滚动高度与底部位置保持；第一次打开一个会话仍支付完整的首次排版。
- 缓存以宿主的节点键稳定为前提。消息被编辑或撤回时分叉出新的键，旧高度不会命中；宿主若改变键的含义，缓存会给出错误高度，需要重审。
- 字体在首次挂载之后才到达会改变行高；`contain-intrinsic-size` 的 `auto` 会随渲染更新已渲染行的高度，未渲染行保留的记录在下一次重新排版时被替换。
- 缓存只活在这一次页面加载里，刷新后重新积累；它以数字和字符串为值，不持有节点。
- 观察总线在移除批次上多一次按清单大小的清理。切换与折叠的移除很少，代价小于它省下的留存。

## 重审条件

- 宿主提供行级虚拟化，或直接报告每一行的真实高度时，缓存与标记改读宿主的结果。
- 宿主的聊天节点键不再跨挂载稳定，或高度不再由列宽与界面字号唯一决定时，这条跳过规则退回按真实排版后标记。
- 浏览器给 `content-visibility` 提供跨节点的高度的记忆，或给 `contain-intrinsic-size` 提供按内容键的取值时，缓存可以退场。
