# D104. 上下文分项按内容块与来源拆成八类，占用仍取服务商读数

- **取代**：D99

## 背景

上下文分项已改读实际发送的内容、按字符类别计价、占用取服务商读数。但类目按消息来源粗分：用户消息、助手消息、工具结果各一行，指令文件、技能、其他上下文各一行。读者看不出助手消息里推理、正文、工具调用各占多少，也看不出文件与图片从哪条消息里来；推理与工具调用混在助手消息一行，工具定义与技能、MCP 又分散在三行。按 ReAct 的口径，上下文应能读出 推理（Reasoning）→ 执行（Action）→ 观察（Observation）的结构，静态内容（系统提示、能力定义、注入）与对话正文各自成类。

## 决定

- 计价来源与占用口径不变：分项读宿主会话日志实际发送的内容，计价只在 `packages/contracts/src/tokens.ts` 一处，占用与窗口取服务商读数，分项按各自价格比例分配这份占用，各项之和等于占用，图例百分比以整个窗口为分母。折叠随事件增量进行，消息到达时定价一次，替换范围（压缩、裁剪）扣回其价格。
- 类目拆成八类：系统提示；工具、技能和MCP；对话正文；推理过程；执行过程；工具结果；文件与图片；上下文注入。
- 拆分先按内容块、后按来源：任何消息里的 reasoning 块归推理过程，tool-call 块归执行过程，image 与文件块归文件与图片；剩余文本按消息来源归类。助手的推理取残差——助手消息总价减去正文、执行过程、文件与图片，不可见推理与未知块一并落入，保证无论推理是否可见都被计量。
- 对话正文是用户与助手的文本正文：无来源标注的用户文本与助手文本归对话正文；带技能标注（目录、调用、技能正文）归工具、技能和MCP；指令文件与其他带来源注入（运行时上下文、子智能体转发、任务通知）归上下文注入。
- 工具、技能和MCP 合并为一行，名称随构成动态变化：三者齐全显示「工具、技能和MCP」，无 MCP 显示「工具和技能」，无技能显示「工具和MCP」，仅工具显示「系统工具」。工具定义与 MCP 仍从请求头计价（`mcp__` 前缀单列），技能目录、调用与正文按来源标注与 `<skill_content` 开头标记识别；技能正文里的图片先提取到文件与图片。
- 系统提示保留每一条仍存活的提示，不再把被顶替的旧提示降级到其他上下文。
- 未知块默认归载体：助手的未知块入推理残差，其余消息的未知块入该消息的来源类目。
- 分项按分配到的代币数从大到小排列，色块自左向右同序，相同大小保持类目顺序；剩余空间不参与排序，固定最后一行。
- 八类配色沿用既有类目色并补两色：系统提示黄、工具、技能和MCP 橙、对话正文蓝、推理过程紫、执行过程洋红、工具结果青、文件与图片绿、上下文注入灰。

## 后果

- 读者能读出助手消息里推理、正文、执行各占多少，文件与图片独立成类，能力定义（工具、技能、MCP）聚成一行且名称自描述。
- 推理残差口径把不可见推理与未知块计入推理过程，推理栏可能略高于可见推理文本；这是「无论可见与否都计量」的取舍。
- 全局字符费率拟合在留出会话集上泛化良好（D103）；逐语境乘数经留出验证被否决（过拟合），不采用。
- 放弃的做法：按消息来源粗分（原类目）；把推理单列为可见 reasoning 块之和（漏掉不可见推理）；逐语境乘数微调（留出集更差）。

## 重审条件

- 宿主提供按类别归因的上下文投影时，改读该投影，删掉本插件的折叠与计价。
- 服务商分词器更换、字符费率明显偏离时，重跑约束拟合更新常数（D103）。
