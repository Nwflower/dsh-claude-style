# D110. 会话总览是宿主会话面板里的几节，数据仍由宿主半边折叠

- **取代**：D106、D102、D94

## 背景

此前的会话总览是皮肤自绘的一列：挂在页面上的 React 根、`position: fixed` 贴住对话列的右边缘、按窗口与对话列宽度自动开合、给对话主体加外边距挤出位置。当时宿主没有为这一列留扩展点，D43 允许用 DOM 与样式补齐。

宿主 0.2.3-alpha.2 加入了会话面板 `@deepseek-ai/dsh-client-ui-session-panel`。它是对话视图右侧的一块面板：宿主自己决定停靠还是浮层、何时有位置停靠、开关按钮放在会话头部、停靠偏好存在浏览器里、进出动画与对话的让位用同一段时长。面板由若干节组成，每节是槽位 `conversation.session.panel.section` 里的一项；环境一节的行是槽位 `conversation.session.panel.environment.row` 的列表；节标题右侧是按节 `id` 分发的 `conversation.session.panel.section.actions`；行的悬停卡片与列表折叠各有一个工厂槽位；所有行共用一套标记属性（`data-session-panel-row` 与 `data-row-part`），样式由面板统一给出。宿主自己注册了环境（工作目录一行）、变更请求、子智能体、共享任务与后台任务五节。

那份决定的重审条件写明：宿主为右侧详情列提供官方槽位时，改用宿主的，删掉自绘的定位、阈值与挤压规则。皮肤自绘的一列与宿主面板现在同时站在对话右侧，「环境」与工作目录画了两遍，子智能体与后台任务各有两份列表。

## 决定

- 会话总览进入宿主的会话面板。皮肤不再挂自己的列、不再画会话头部的详情按钮，也不再有自动开合阈值、手动收起的记忆、主体外边距与宽度过渡；停靠、浮层、开关、偏好、进出动画与节的拖动排序都由宿主面板负责。
- 皮肤向 `conversation.session.panel.section` 注册四节，`id` 以 `claude-style-` 开头，`order` 位于环境（0）与变更请求（100）之间：上下文（10）、会话统计（20）、Token 用量（30）、产出（40）。节标题取自皮肤自己的文案，标题右侧不放读数。
- 宿主面板的节没有开合：两张数字表始终展开。标题右侧的读数是为收起的节准备的摘要（占比与小色条、输出速度、费用、条目数），节展开时它重复正文里已有的数字，因此自绘列里节的原生折叠控件与这些读数一并删除，皮肤不向 `section.actions` 注册任何内容。
- 环境一节的工作目录由宿主的 `project` 行承担，检出、分支、本地变更与连接由宿主 forge 包的行（`order` 20 到 40）承担，皮肤的目录行与分支行删除，宿主半边的路由也不再读 Git，只回答会话的工作目录供产出定位与打开文件。皮肤向 `conversation.session.panel.environment.row` 注册两行：本机（排在 `project` 之前）与预设（`order` 50，排在宿主各行之后收尾，提示是预设自己的说明）。
- 工作类的信息交给宿主自己的节：变更请求、子智能体、共享任务与后台任务。皮肤删除进程、任务、子智能体、团队与变更五节，宿主半边的路由不再折叠作业、子智能体、团队与变更请求，也不再提供单个作业输出的读取。前台命令调用的历史不再进入面板，读者在转写里读它。
- 行使用宿主的行标记：`data-session-panel-row` 的行、`data-row-part` 的 `body`、`icon`、`content`、`lines`、`detail`、`trailing`，可点击的行用 `button` 作为 `body`。行的高度、字号、墨色、悬停底板与焦点环跟随宿主面板，皮肤的样式表只为宿主没有对应部件的内容写规则：上下文的占用条与图例、压缩控件、数字表与占位条。行的完整信息用宿主的 `conversation.session.panel.details` 工厂放进悬停卡片，产出的列表超过宿主的行数上限时用 `conversation.session.panel.fold` 工厂折叠。
- 面板停靠在转录旁时，皮肤把它画成一叠卡片，每节一张：面板本身不铺底色、不投阴影，各节各自带底色、圆角与一圈细线，卡片之间留同样的间距，站在对话的画布上，与 Claude Code Desktop 的详情栏一致。卡片的细线与宿主画在相邻节之间的分隔线同色同宽，宿主那条线落在卡片上沿时就是卡片自己的边，皮肤不需要压过宿主那条高优先级的规则。浮在转录上方的浮层保留宿主的整张卡片：卡片之间的空隙会露出底下的文字。面板在停靠与浮层两种状态下都不画滚动条，仍可滚动：滚动条贴在卡片外侧会读成第二道边线；宿主为滚动条预留的槽位与透明右边框随之去掉，浮层的右内边距回到与左侧相同的 8px。节标题是面板的界面标签，皮肤的标题衬线字体不进入面板。
- 一节没有内容时渲染为空，宿主面板据此隐藏整节。首帧规则延续：上下文、会话统计与 Token 用量在宿主路由回答前用与最终行同高的占位条站出来；产出只在回答里有文件时出现，首帧不为它占位。
- 同一会话的几节共享一份读数：读数按会话建一个来源，第一节挂上时开始轮询，最后一节卸下时停止。轮询规则延续自绘列的做法：一次只允许一个请求在飞，新的请求作废旧的，相同的回答不进入渲染，页面不可见时不取数，宿主落下统计帧时越过它保留的答案再问一次；读数记在回答它的会话名下，新会话首次请求失败时显示失败，不保留旧答案。两张数字表读统计功能发布的那一份实时读数，与底部那行读数同源同刻。
- 宿主面板显示时，页面上保留皮肤自己的标记：会话头部的预设标签让位给环境一节的预设行；会话头部宿主的子智能体与后台任务入口让位给面板里的对应节；「对话统计信息位置」的「跟随会话面板」一档在面板显示时不绘制输入区下方那行统计，那一行保留自己的盒子。标记跟随面板元素是否在页面上，元素的选择器登记在契约模块里。
- 宿主没有会话面板槽位时，皮肤注册的各项等待槽位声明，页面上不出现总览；皮肤不再自绘替代的列。

## 后果

- 面板的位置、宽度与开合完全跟随宿主：宿主改了停靠规则或动画，皮肤不用跟着改。皮肤对面板外观只改停靠时的卡片层次，依赖宿主节元素的 `data-session-panel-section` 与面板的 `data-session-panel` 两个标记，以及宿主分隔线的颜色与宽度；宿主改了这两处，卡片的细线可能与它那条分隔线叠成两条。
- 宿主面板按节的 `id` 记住读者拖出的顺序；皮肤的节 `id` 一旦发布就保持不变，改名会让读者排好的顺序失效。
- 删除工作类各节后，前台命令的输出与停止按钮不再出现在面板里；后台作业的停止走宿主后台任务一节自己的控制。
- 宿主的节没有折叠，两张数字表常驻展开，面板比自绘列更长；面板自己滚动，没有滚动条提示还有多少内容。
- 放弃的做法：保留自绘列并隐藏宿主面板（与宿主的开关按钮、停靠让位冲突，宿主升级时两套逻辑互相打架）；把整份总览注册成宿主面板里的一节（无法利用宿主的节排序与空节隐藏，环境一节仍会重复）。

## 重审条件

- 宿主为面板的节提供开合能力时，两张数字表改回初次挂载时收起，收起的节在标题右侧重新给出读数。
- 宿主把会话统计与用量作为已推送的会话投影交给页面时，改为读投影，删掉路由里的计时与计价折叠。
