# D114. 钠改写只适配宿主并以静默开关呈现

- **取代**：D109、D78

## 背景

宿主的对话流样式里有几条间距规则用 `:has()` 判断一个流条目是否为空，再经兄弟组合子把这一判断传给其后的条目；这几条规则的主体没有类名、标签或属性可供浏览器分桶，页面上每个元素都要拿它去试，长会话里样式重算成本随之上升。插件支持的宿主最低版本已高于早期适配表的版本起点，无需再维护宿主版本读取与 bundle 列表分支。与此同时，原决策在「通用」设置页的小字里向终端用户展示生效规则条数，并在悬停气泡中列出内部成员标识、样式表文件名与原始 CSS 声明文本，属于内部调试细节向用户界面的外露。

## 决定

- 适配表只持有宿主的适配项：每个适配项写明样式表（加载器标在样式节点上的包名与路径）、它认得的规则，以及维护兜底标记的脚本。成员不声明版本来源与起始版本，引擎不读宿主版本，也不读 profile 的 bundle 列表。
- 开关打开时，适配表里登记的规则在原样式表里就地改写选择器，让浏览器能给它们分桶；关闭时选择器原样写回、皮肤写的标记全部撤下，页面回到宿主默认样式。
- 表里写的是整条选择器：浏览器序列化出来的样子，带哈希的类名按角色占位，第一次出现时捕获，之后必须是同一个类名。差一个字就匹配不上，规则保持原样；宿主改了规则，页面保留宿主自己的规则。
- 改写只动主体：把它按宿主在创建元素时就写上的键展开成并列的几支，浏览器按这些键分桶，只拿这些元素去试。元素一插入就带着键，宿主在同一个任务里插入节点又同步读布局时，改写后的规则与原规则命中同一组元素。规则里的结构判断原样留给浏览器实时判定。
- 宿主或别的插件放进流里的其他种类，由脚本写在流容器每个子元素上的标记兜底：它是并列的最后一支，在变化观察的回调里写上。
- 替换与原规则等价：对同一棵树命中同一组元素，优先级相同。为补上键占去的那一份优先级，并列的否定条件合进同一个 `:not()`，只计其中最重的一项。
- 开关默认关闭，偏好的初值是「未决定」。读到用户设置之后的探测里，适配表一有规则命中，就替用户打开；用户拨过一次开关，探测不再改它。
- 设置页只展示「钠（Sodium）渲染引擎」开关与简明性能说明，不在界面中展示生效规则计数、失效提示或原始 CSS 规则悬停列表；运行态命中集合保留在内部状态供测试与开发者工具检查。

## 后果

- 开关打开时，宿主的样式表与它作者写下的样子不再一一对应；排查样式问题前先关掉开关。
- 用户界面保持干净，不再把内部样式表文件名、选择器成员名与 CSS 声明暴露给普通用户。
- 适配一条新规则要同时写出它的整条选择器、替换写法与它依赖的宿主契约，并由机制规范核对两者在同一棵树上命中同一组元素、在层叠里分量相同。
- 宿主每次改动这些规则，表里对应的一条就失效，需要按新的写法重新登记；改写作用在样式表对象上，同一份样式被重新注入时改写随旧对象一起丢失，由 `<head>` 观察器对新对象重新匹配。
- 放弃的方案：在皮肤样式表里写更高优先级的规则覆盖宿主声明（浏览器仍要求值原规则）；删除原规则并插入副本（宿主增删规则会让索引失效）；在设置页直接向用户展示命中规则计数与原始 CSS 声明气泡。

## 重审条件

- 宿主修掉这些规则，或为流条目提供可分桶的属性时，对应的适配项删除。
- 浏览器对这类结构选择器的匹配与失效成本降到与普通属性选择器相当时，整个功能删除。
